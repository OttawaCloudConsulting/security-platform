<objective>
Build the two shared pieces every later plan depends on: three standalone ecosystem detectors, and a
smoke-gate harness that can express "exit code 2 means findings" and "this report is an error object,
not a result".

Purpose: 16-PATTERNS Open Decision 1 records that RESEARCH is internally inconsistent about whether the
detectors are inline workflow shell or extracted scripts. The user resolved it: extracted scripts. That
choice is load-bearing, not cosmetic — inline duplication would mean the Criterion 4 negative test
exercises a *copy* of the CI logic rather than the logic CI runs. Separately, `run_scan()` hard-codes
rc=1 as PASS, so a healthy tflint run reporting real pinning findings (rc=2) would be recorded as a
"tool/infrastructure error", and Phase 15's own retro records that using the wrong helper "inverted
their pass/fail verdict during first live test".

Output: `scripts/detect-npm.sh`, `scripts/detect-python.sh`, `scripts/detect-terraform.sh`, and a
`scripts/smoke-scans.sh` whose helpers and preflight can express the three new sub-scans. The sub-scan
sections themselves are 16-03; this plan changes no scan behaviour.

<notes>
**TARGET REPOSITORY.** All four files live in `repos/security-platform/scripts/`. Use
`git -C repos/security-platform` for every git operation. Never push from the outer repo.

**Never set the executable bit** (`.claude/rules/defensive-protocol-v2-anti-slop.md`). The shebang is
documentation only; every invocation is `bash scripts/<name>.sh`, never `./scripts/<name>.sh`, never
`sh scripts/<name>.sh`. Do not run `chmod +x` on anything in this plan.

**No `mapfile`.** 16-RESEARCH Pitfall 10 measured `/bin/bash` on this workstation at 3.2.57; `mapfile`
is a bash-4 builtin. The existing `smoke-scans.sh` is bash-3 compatible (`FAILURES+=()` only). Use
`while IFS= read -r` loops in the shared scripts so the minimum stays where it is. RESEARCH's own code
examples use `mapfile` — those examples were written for inline CI shell, where bash is 5.x; they are
not authoritative for a shared script.

**The `$GITHUB_OUTPUT` trap** (16-PATTERNS §6): a script that appends to `"$GITHUB_OUTPUT"`
unconditionally dies on a workstation under `set -u`, where the variable does not exist. Guard the
append with `[ -n "${GITHUB_OUTPUT:-}" ]` inside the script. Do not solve this by having the caller
export `GITHUB_OUTPUT=/dev/null` — the guard must live in one place, identically, in all three scripts.

**Do not add scan behaviour in this plan.** The three sub-scan sections and the negative skip test are
16-03. This plan ends with the existing five scanners still passing through the generalised helpers,
proving the refactor is behaviour-preserving.
</notes>

    - `exit 0` on every path, including the zero-match path. A detector that exits non-zero on "nothing

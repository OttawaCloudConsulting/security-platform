<objective>
Author the two fixtures this phase's entire validation rests on — `fixtures/vulnerable.py` (SAST seed,
D-01) and `fixtures/secret.env` (Secrets seed, D-02) — and prove each one fires its intended named rule
locally, against the exact tool versions CI pins, before a single byte reaches GitHub.

Purpose: SC1 asks for "a detection from each of the five jobs". Three of the five already have permanent
fixtures on `main`; SAST and Secrets do not. Every later plan in this phase measures something. This is the
only plan that *builds* something, and if either fixture is silent, every subsequent measurement measures
nothing. RESEARCH measured two traps that a fixture written from training knowledge falls straight into:
`AKIAIOSFODNN7EXAMPLE` produces ZERO Gitleaks findings (the default config allowlists `EXAMPLE`-suffixed
keys), and `os.system()` produces ZERO Semgrep `p/default` findings. Both traps are avoided here by
construction and re-verified by measurement.

Output: two committed fixture files on a fresh `feature/phase-19-…` branch cut from `origin/main`, a
recorded pre-fixture Semgrep baseline, and a recorded post-fixture measurement scoped by rule id and path.

Sequencing note: every plan in Phase 19 is strictly sequential (wave 1 through wave 7). They share one
local working tree (`repos/security-platform`), one live GitHub repository, and one long-lived validation
PR. Two same-wave executors would collide on `git checkout`. There is no parallelism available in this
phase and none is claimed.

silently.

**Five green checks are the expected result here**, because report-only sets `continue-on-error: true` on
every scan step. Green does NOT mean clean, and the SUMMARY must not phrase it that way. What would be a
failure: fewer than five `security / …` checks present, a job that died before its scan step, a missing
artifact, or a fixture whose named rule is absent from its report.

**Do not add a `push:` trigger, rename the `security` job, or edit any workflow file.** All four are outside
this phase's boundary and two of them silently reverse locked decisions.

**`$SCRATCH` must be set inline in every command that uses it.** Shell state does NOT persist between
tool calls in this harness, so a `$SCRATCH` exported in one call is empty in the next. Prefix every
command and every verify invocation that references it with `SCRATCH=<absolute session scratchpad path>;`
in the SAME command. Use the scratchpad path from your own environment prompt — never `/tmp`, never a path
copied from this plan, and never anywhere inside either repository.

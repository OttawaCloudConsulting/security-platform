`repos/security-platform/.github/workflows/security.yml` (or from a live `commits/<sha>/check-runs` capture) and
prefix them with `security / `. The separator is EM DASH U+2014; a hyphen or en dash renders identically in most
fonts and produces a permanently-pending required check. There are FIVE, not six — the `security` caller job

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| documented ruleset procedure → live repository settings | A wrong body deletes protections; a wrong context name creates a permanent block |
| documented gate-mode switch → enforcement reality | A setting that looks enforcing without being enforcing is worse than an advisory one |
| documented job removal → required-check list | Removing a job whose context is required blocks every pull request forever |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-20-08 | Tampering | ruleset whole-document `PUT` | mitigate | The guide gives the read-modify-write helper and its refusals, states that a bare `PUT` deletes `deletion` and `non_fast_forward`, and requires `bypass_actors` be carried forward verbatim |
| T-20-09 | Elevation of privilege | required-check theatre and permanently-pending contexts | mitigate | D-07 ordering as a numbered sequence with ADR-017's step-1 correction; contexts read from `commits/<sha>/check-runs` with `app.id == 15368`; read back from `rules/branches/main`, never the classic 404 |
| T-20-20 | Denial of service (self-inflicted) | `blocking` plus required checks with no bypass actor | mitigate | Self-lockout warning with the measured `bypass_actors: []` / `current_user_can_bypass: "never"` evidence and the "require only after a clean blocking run" rule |

<objective>
Close the last unmeasured behaviour in the shipped pipeline: what a PRIVATE consumer actually experiences.

Purpose: 37 of the account's 60 repositories are private, so this is the majority adoption path, and it is the one
this project has only ever reasoned about. Plan 01 measured a single SARIF upload attempt in isolation; plan 04
acted on that measurement; plan 06 proved the guard does not misfire on a PUBLIC repository. None of that shows
what a private consumer sees when the whole pipeline runs. 20-VALIDATION.md lists this as a manual-only
verification for exactly that reason. Getting it wrong in a way nobody looks at is how a pipeline ends up
permanently red — or worse, permanently green with nothing uploaded and no assertion left to notice.

Output: an observed private-repository run, and either a confirmation that `v1` is correct for private consumers
or an explicit operator decision about correcting it.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| private repository → code-scanning ingestion | The capability is absent; the pipeline must degrade visibly, not silently |
| capability guard → assertion coverage | A guard that over-matches removes a real assertion; one that under-matches turns every private consumer red |
| observed outcome → documented claim | The guide already asserts private behaviour; this run is what makes that claim evidence |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-20-05 | Repudiation | the six SARIF verify steps on a private consumer | mitigate | Each outcome read individually; `skipped` confirmed as intended, `failure` and `success` both treated as defects requiring a `v1.0.1` decision |
| T-20-14 | Information disclosure | the five artifact verify steps | mitigate | Measured on a private repository for the first time, closing 17-04's explicitly unmeasured belief about `ACTIONS_RUNTIME_TOKEN` |
| T-20-23 | Information disclosure | scan artifacts on a private repository | accept | Artifacts are visible to anyone with repository read access, which on a private repository is the intended audience; retention stays 90 days |
| T-20-06 | Tampering | advancing the moving `v1` tag | mitigate | Any correction goes through a new plan with a host proof run before `v1` moves; the force-push procedure is recorded rather than improvised |
| T-20-SC | Tampering | package-manager installs | accept | None; the private pilot's own `package-lock.json` is scanned, never installed from |

`SLUG=$(git -C repos/security-platform remote get-url origin | sed -E 's#^.*github\.com[:/]##; s#\.git$##')`
and pass it as `-R "$SLUG"` (or `repos/$SLUG/…` for `gh api`). Never run a bare `git` command — the
`cd` working directory resets between calls and a bare command would hit the outer documentation repo,
whose history is disjoint from this remote.

**Why the merge is a human checkpoint, not an autonomous step.**
`.claude/rules/defensive-protocol-v2-session-management.md` (Irreversible Actions) requires explicit
user confirmation before merges and architectural commitments. This merge is both: it puts the repo's
first ACTIVE CI workflow tree on the default branch, where Phases 15-20 build on it.

**A missing Dependabot PR does NOT mean failure.** Assumption A7 in RESEARCH is unverified: the
deliberate-v7.0.0-pin strategy assumes Dependabot resolves the pinned SHA back to its tag
(`9c091bb…` → `v7.0.0`) and compares against the latest release. If it instead reads the trailing
`# v7.0.0` comment, or if upstream state differs, no PR appears. Four outcomes must be told apart,
because only one is a defect:
  - a bump PR appears                                  → criterion #4 WITNESSED
  - no PR, job log says "up to date / no updates"      → wiring PROVEN, criterion #4 INFERRED
  - no PR, job log shows a config/parse error          → wiring BROKEN — STOP and REPORT
  - no job ran at all                                  → config is not on the default branch (re-check the merge)
A missing PR examined in isolation proves nothing either way. The job log is what turns a null
result into information.

**Dependabot's job log is UI-only.** No REST endpoint triggers or exposes a Dependabot version-update
job; the log lives at Insights → Dependency graph → Dependabot, and the only manual trigger is the
"Check for updates" button there. That is why the classification step is a human checkpoint rather
than something the executor can resolve alone.

**Don't over-specify the expected bump target.** Assert the bump moves *away from*
`9c091bb21b7c1c1d1991bb908d89e4e9dddfe3e0` to some other 40-hex SHA with an updated same-line version
comment. Do NOT hard-require `3d3c42e5aac5ba805825da76410c181273ba90b1` / `v7.0.1` — a newer patch
may have shipped since research on 2026-09-10.

**Dependabot will never touch the local caller reference.** `uses: ./.github/workflows/security.yml`
is ignored by design (local refs have no version to update). `actions/checkout` is the only
Dependabot-tracked dependency this phase introduces. Its absence from any Dependabot PR is correct,
not a bug. Note that `cicd/.github/workflows/security.yml` in the same repo is NOT scanned either —
Dependabot's `github-actions` ecosystem at `directory: "/"` reads only the ROOT `.github/workflows/`
plus a root `action.yml`.

**Other PRs exist on this repo.** PR #3 ("feat: phases 11-12 …") was already open at planning time.
Always filter Dependabot PRs by `--author "app/dependabot"`, and reference the Phase 14 PR by the
number recorded in `14-02-SUMMARY.md` — never by "the most recent PR".

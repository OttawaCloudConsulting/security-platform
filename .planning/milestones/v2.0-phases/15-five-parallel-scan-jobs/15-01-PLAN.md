**TARGET REPOSITORY — read this before anything else.**
Every deliverable in this plan lands in the product repository checked out at
`repos/security-platform/` (remote `https://github.com/OttawaCloudConsulting/security-platform.git`).
`fixtures/` means `repos/security-platform/fixtures/` — the top level of the *target* repo, because

**RESEARCH-DRIVEN CORRECTIONS TO LOCKED DECISIONS — read before writing any fixture.**
Two locked CONTEXT decisions rest on assumptions that were falsified by commands run during research.
The corrected values are binding; the literal CONTEXT wording is not. Flag this in the SUMMARY.

- **D-02 "old base image with known CVEs" is backwards** (RESEARCH C-1). An EOL distro has no advisory
  feed: `FROM alpine:3.14` scans as `0 vulnerabilities` with `WARN This OS version is no longer
  supported`. That would violate Success Criteria #2. The corrected criterion is a *currently
  supported* distro carrying unpatched CVEs — `public.ecr.aws/docker/library/debian:12-slim` pinned by
  digest, measured at 222 vulnerabilities (4 CRITICAL, 52 HIGH) on 2026-09-10. D-02's intent
  (guaranteed real findings) is preserved; its literal wording is not.
- **D-02 "unpinned/old Terraform provider" produces zero Checkov findings** (RESEARCH C-2). Provider
  pinning is invisible to Checkov — that is Phase 16 / SCA-03 territory, enforced by a different check.
  Keep the old `hashicorp/aws 3.74.0` pin anyway (it satisfies D-02 literally and seeds Phase 16), but
  the IaC job's findings come from misconfigured *resources*: an unencrypted `aws_s3_bucket` and an
  `aws_security_group` with `0.0.0.0/0` on port 22. Measured: 12 failed checks together.
- **D-03's `.gitleaksignore` exemption is unnecessary and mechanically wrong** (RESEARCH C-3).
  Unnecessary: no fixture contains a secret, so the pre-push Gitleaks hook never fires
  (`gitleaks dir` → 0 findings, exit 0). Wrong: `.gitleaksignore` accepts *fingerprints only*
  (`file:rule-id:start-line`), not path globs; a path allowlist would need `.gitleaks.toml`, which is
  repo-root config and would also blind the CI secrets job. **Make no Gitleaks change.** D-03's
  *scoping intent* is honored by the four `exclude: ^fixtures/` entries in Task 1 — those are the
  hooks that actually block the fixture commit (RESEARCH C-4).

**Branch creation IS this plan's job — a deliberate deviation from 14-01.** Plan 14-01 forbade
`git switch` because the product repo was then sitting on a diverged `feature/phase-12-*` branch with
an open PR #3. That condition is gone: RESEARCH C-6 and a direct check confirm the repo is on `main`,
clean, with PRs #4 and #5 merged. Cutting a fresh branch from `origin/main` is safe and trivially
reversible, and the automation-first rule says do it rather than stall. Any *other* starting state —
dirty tree, or HEAD not on `main` — is STOP/REPORT/WAIT, not something to fix.

**Never use `SKIP=` or `git commit --no-verify` to land the fixtures.** That is precisely the blanket
bypass D-03's scoping intent rules out. If a hook blocks the commit, the fix is a `^fixtures/`-anchored
`exclude:` on that specific hook, or a STOP/REPORT if the hook is one of the four already handled.

**Second-order effect to state in the SUMMARY:** `.pre-commit-config.yaml` governs every future commit
in the target repo. The excludes must stay `^fixtures/`-anchored — a blanket exclude would silently
disable Dockerfile/Terraform/npm gating repo-wide.

**Version-split note (PATTERNS conflict #5), carry to the SUMMARY, change nothing:** `versions.conf`
pins `TRIVY_VERSION="0.69.3"` / `GITLEAKS_VERSION="8.30.0"` and is *generated by* `workstation/setup.sh`;
the CI workflow (Plan 03) will pin Trivy `v0.74.0` / Gitleaks `8.30.1`. Editing `versions.conf` by hand
is out of scope and would be overwritten. Whether workstation and CI versions should converge is a
later-phase decision.

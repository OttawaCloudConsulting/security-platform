**Step 2: Run all 6 scans**

Run each scan command from the aws-zabbix-monitoring-solution root. All commands are PERMISSIVE (no --fail-on, no --error flags). Some tools exit non-zero on findings -- this is expected, not an error. Use `|| true` for Gitleaks and Checkov to prevent shell errors.

IMPORTANT: Scan timeouts can occur. Allow up to 5 minutes per tool. Semgrep first-run downloads rules (30-60s). Grype and Trivy may download vulnerability DBs.

1. **Trivy** -- filesystem vulnerability scan:
```bash
trivy fs --scanners vuln --format json --output reports/trivy-results.json .
```

2. **Syft** -- SBOM generation (CycloneDX-JSON format):
```bash
syft dir:. -o cyclonedx-json=reports/sbom.json
```

3. **Grype** -- SCA vulnerability scan (direct directory scan, not SBOM-based):
```bash
grype dir:. -o json > reports/grype-results.json
```

4. **Semgrep** -- SAST scan with auto config:
```bash
semgrep scan --config auto --json --output reports/semgrep-results.json .
```

5. **Checkov** -- IaC scan (stdout redirect, not --output flag):
```bash
checkov -d . -o json > reports/checkov-results.json 2>&1 || true
```

6. **Gitleaks** -- secrets detection (exit code 1 = findings found, not error):
```bash
gitleaks detect --source . --report-path reports/gitleaks-results.json --report-format json || true
```

**Step 3: Verify all 6 JSON files exist with size > 0**

All 6 must show PASS. If any show FAIL, investigate the specific tool's output for errors.

**Special case -- Gitleaks no-findings:** If Gitleaks finds zero secrets, it may not create the report file (exits 0, no output file). Per CONTEXT.md, empty results are valid. However, the aws-zabbix repo likely has CDK asset hash findings, so the file should exist. If the file does not exist, this is still acceptable for TOOL-07/TOOL-08 (tool ran successfully, just had no findings to report).

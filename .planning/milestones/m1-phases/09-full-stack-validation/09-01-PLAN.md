  <action>
    1. Create `repos/terraform-pipelines/.markdownlint.json` with the same disabled rules as aws-zabbix:
       ```json
       {
         "MD013": false,
         "MD024": false,
         "MD033": false,
         "MD036": false,
         "MD040": false,
         "MD041": false,
         "MD049": false
       }
       ```
       These rules are disabled because:
       - MD013: line length -- documentation files regularly exceed 80 chars
       - MD024: duplicate headings -- legitimate in multi-section docs
       - MD033: inline HTML -- used in documentation
       - MD036: emphasis as heading -- false positives on bold text
       - MD040: fenced code language -- not all code blocks need language tags
       - MD041: first line heading -- not all markdown files start with H1
       - MD049: emphasis style -- mixed emphasis is acceptable

    2. Create `repos/terraform-pipelines/.markdownlintignore` with entries appropriate for terraform-pipelines:
       ```
       .terraform/
       .claude/
       .planning/
       agents/
       ```
       Note: terraform-pipelines has no node_modules or cdk.out (those are aws-zabbix specific), but does have .terraform directories that should be excluded. Include .claude/, .planning/, and agents/ to match the pattern from aws-zabbix of excluding working memory directories.

    3. Stage and commit both files in terraform-pipelines on the feature/add-pre-commit branch. Use commit message: "chore: add markdownlint config for pre-commit validation". Add only the two specific files.
  </action>

    <automated>cat repos/terraform-pipelines/.markdownlint.json | python3 -c "import sys,json; d=json.load(sys.stdin); assert d.get('MD013') == False; print('OK')" && test -f repos/terraform-pipelines/.markdownlintignore && echo "ignore file exists"</automated>

    - Both files are committed to the feature/add-pre-commit branch

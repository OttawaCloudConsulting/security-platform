<objective>
Turn exactly one of the five checks red on the exercise pull request by flipping a repository
variable — nothing else — and measure the pull request's merge verdict while that red check is NOT
yet required. That verdict is the control observation. Without it, a later `BLOCKED` reading cannot
be attributed to required-status-check enforcement rather than to the `pull_request` rule, to
`copilot_code_review`, or to anything else on the ruleset.

Purpose: the phase's whole evidentiary weight rests on a transition measured on one tree hash. This
plan produces the "before" half and then immediately closes the repository-wide blocking window,
because the check conclusions persist on the commit long after the variable is gone — the window does
not need to stay open across the human checkpoint in plan 03, and leaving it open would expose every
unrelated run on the target repository for the duration of a human's response time.

Output: a red check on a known tree hash, the control merge verdict, a bounded and audited gate
window, and the offline fixture plan 03's guard rehearsal needs.

This plan makes NO ruleset write. The ruleset is untouched until the operator runs `--apply` in
plan 03.
</objective>

Capture the full output. For each violation, apply the correct fix:

**Fix strategy (from RESEARCH.md):**

1. **SC2086 (unquoted variable) -- simple value variables:** Add double quotes.
   - Example: `echo $CHECKS_PASSED` becomes `echo "$CHECKS_PASSED"`
   - Example: `echo $UBUNTU_VERSION` becomes `echo "$UBUNTU_VERSION"`
   - Example: `echo $PACKAGE_NAME` becomes `echo "$PACKAGE_NAME"`
   - Example: openssl args like `${KEY_SIZE_CA}` become `"${KEY_SIZE_CA}"`

2. **SC2086 (unquoted variable) -- intentional word splitting:** Suppress with inline comment on the line ABOVE the violation.
   - Variables that expand to multiple CLI flags (e.g., `$AWS_PROFILE_FLAG` expanding to `--profile name`) MUST be suppressed, not quoted, because quoting changes word-splitting behavior.
   - Add: `# shellcheck disable=SC2086` on the line above.

3. **SC2154 (variable referenced but not assigned):** Suppress with inline comment if the variable comes from the environment or is set by a calling script.
   - Add: `# shellcheck disable=SC2154` on the line above.

4. **SC2016/SC2064 (heredoc variable expansion):** Leave heredoc quoting as-is. The mix of quoted (`<<'EOF'`) and unquoted (`<<EOF`) heredocs is intentional. Suppress if flagged.

5. **All other ShellCheck codes:** Read the warning message, determine if fixing is safe (does not change runtime behavior). Fix if safe, suppress with `# shellcheck disable=SCXXXX` if not.

**CRITICAL: Do NOT change heredoc quoting (quoted vs unquoted). Do NOT quote variables used for intentional word splitting (multiple flags in one variable). Do NOT add `.shellcheckrc` -- use inline comments only.**

After fixing, re-run to verify all violations are resolved:

(a) Prerequisites (lines 627-634). Rewrite the paragraph; do not append to it. Keep the first sentence about reachability from the runner, then state the two supported routes:
- a public URL, reached from GitHub-hosted runners;
- a private-network instance, reached through a self-hosted runner that the caller names in `DEFECTDOJO_RUNS_ON`.

For the self-hosted route, state that it uses an actions-runner-controller runner scale set whose pods can resolve and reach the instance, and that only the DefectDojo Import and DefectDojo Cleanup jobs move to it while the five scan jobs stay on `ubuntu-latest`. Delete the sentences "is not covered by this guide" and "belongs to a later phase of this project (Phase 29)". Keep "An unreachable URL does not break your pipeline".

(b) Settings (lines 664-686). After the `DEFECTDOJO_URL` line, add a `gh variable set DEFECTDOJO_RUNS_ON --body <runner-scale-set-name> -R OWNER/REPO` line in the same form as the existing lines, followed by a `## ...` comment. The comment says the variable is optional, that unset means both jobs keep `ubuntu-latest`, that the value is the runner scale set name (the `runs-on` label), and that it is read from the caller repository exactly like `DEFECTDOJO_URL`. It also says the variable is available from workflow release v1.2.0, which the `v1` tag follows.

(c) What You Will See (lines 776-795). Add a paragraph on queue behaviour. When the named runner is offline, or has gone 30 days without a runner software update, the import job **queues** rather than fails. GitHub cancels a job that has been queued for about 24 hours. Merge is unaffected because the job is not a required check, and it must never be made one.

(d) Caveats (lines 796-805). Add three bullets:
- **Per-repository scale sets:** on a personal GitHub account there are no organisation runner groups, so each consumer repository needs its own repository-scoped runner scale set. Its credential is a fine-grained PAT limited to that repository, with Administration: Read and write, which is broader than runner management alone.
- **Fork pull requests on public repositories:** before setting `DEFECTDOJO_RUNS_ON`, raise the repository's Actions setting to require approval for all external contributors (`all_external_contributors`). A fork PR runs its own copy of the workflow and could otherwise target the self-hosted label.
- **The runner image must be kept current:** runners that skip updates for 30 days stop receiving jobs.

(e) Line 681's honesty sentence ("None of these commands was executed against any pilot repository") stays as it is. Plan 29-19 revisits it after the live proof.

Do not write any IP address, homelab hostname, node name or kube context name. Use placeholders such as `OWNER/REPO`, `<runner-scale-set-name>` and `https://defectdojo.example.com`.

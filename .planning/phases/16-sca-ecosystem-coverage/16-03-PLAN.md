<objective>
Prove all three new sub-scans locally, against the real fixtures, before a single line of workflow YAML is
written. Add npm audit, pip-audit and tflint sections to `scripts/smoke-scans.sh`, each asserting on
report CONTENT rather than exit status, plus the Criterion 4 negative test that runs each detector in an
empty git repository.

Purpose: Phase 15's established order is prove-locally-then-push, and here it is load-bearing rather than
stylistic. `npm audit` and `pip-audit` both return exit code 1 for "vulnerabilities found" AND for
"input file missing/invalid" — measured, indistinguishable by exit code. A CI-first approach would show a
green annotated step for an ENOLOCK error and read as "npm scan ran, nothing found": the exact false pass
Success Criterion 4 forbids. The rule-id assertion matters equally: tflint already reports
`terraform_required_version` against the fixture, so an "at least one finding" check would pass without
any pinning rule firing at all.

Output: a `scripts/smoke-scans.sh` that exits 0 only when all four SCA sub-scans produced real,
structurally-valid reports and every detector skipped cleanly on an empty repo — committed on the phase
branch, with the measured counts recorded.
</objective>

**TARGET REPOSITORY.** `scripts/smoke-scans.sh` means `repos/security-platform/scripts/smoke-scans.sh`.
Every git operation uses `git -C repos/security-platform`. Never push from the outer repo.

**The detector contract is fixed by 16-02 — do not re-derive it.** Read `16-02-SUMMARY.md` for the exact
argument, default list-file name, log prefixes and exit behaviour, and call the scripts accordingly.

**pip-audit invocation is a locked decision.** Use the default resolving mode:
`pip-audit -r <file> --format json --progress-spinner=off -o <out>`. Do NOT add `--no-deps`, do NOT add
`--disable-pip`, do NOT add `--require-hashes`. The ~11.5 s cost is accepted for correctness and
consumer-repo generality; `--no-deps --disable-pip` hard-errors on any requirement not pinned with `==`.

**`|| true` discipline.** It is acceptable on the informational count-printing `python3 -c` blocks that
already use it (lines 93-101, 111-125, 150-161). It is forbidden on anything that decides a verdict. An
assertion that swallows its own failure IS the false-pass mechanism Criterion 4 and the project's
anti-slop rule name explicitly.

**Local tool versions differ from CI, deliberately.** The workstation has tflint 0.61.0 against v0.64.0 in
CI, mirroring the already-accepted Trivy/Gitleaks split recorded in 15-05-SUMMARY. The rule ids measured
here must be re-confirmed under v0.64.0 in 16-05's live run rather than assumed — record the local
version in the SUMMARY so the comparison is possible.

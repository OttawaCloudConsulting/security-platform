## NEXUS-03 Evidence Tier (settle this in writing)

The chart's contract ends at the rendered `volumeClaimTemplate`. Whether a PVC then binds to a given
class is Kubernetes' responsibility, not the chart's. Therefore:

| Path | Evidence required | Have it? |
|---|---|---|
| Default (no override) | render omits key (N3-a) + gate check STORAGECLASS-OMITTED + **live** STS has no key and PVC got the cluster default (N3-g/h) | ✓ render + live |
| Override | verifier's own render probes via `--set` and `-f` (N3-b/c) + gate check STORAGECLASS-OVERRIDE + mutation proving the gate discriminates (N3-e) + subchart source line (N3-f) | ✓ render-tier, which is the correct tier |
| Override, live on a cluster | `kind` cluster with a second StorageClass, install with override, observe PVC | **Not recommended** |

**Recommendation: do not add a live override witness.** It costs about 8 minutes of docker/kind work, and a
homelab variant would be a mutation. It also proves nothing the render does not already prove: Kubernetes
binding a PVC to a named class is Kubernetes' own tested behavior. State this reasoning in the
VERIFICATION Method section so the "independently verified" claim is precise about its tier.

## Common Pitfalls

### Pitfall 1 (judgment): NEXUS-01 says "Helm proxy repos configured", but a default install creates 3
**What goes wrong:** A verifier reads NEXUS-01 literally, renders defaults, finds 3 bodies, and marks it FAILED or asks for an `overrides:` entry.
**Why:** D-05 (REVISED, 23-CONTEXT.md:27) deliberately ships no Helm remote. Helm Hub is defunct, Artifact Hub is not a chart repo, and Bitnami is mid-deprecation. The **ROADMAP Phase 23 goal text itself** encodes it: "(Helm proxy is consumer-configured, no universal default exists post-Helm-Hub)". ROADMAP is the contract (verify-phase.md: "Success Criteria from ROADMAP.md are the contract").
**How to avoid:** Mark it **VERIFIED with disclosure, with no `overrides:` entry**. The grounds:
- The contract encodes D-05.
- HELM-REPO-OPT-IN proves the mechanism.
- The live homelab has `helm-proxy` via the overlay (N1-g/h).
- The v3.0 audit accepted NEXUS-02's opt-in default as SATISFIED without override: the same pattern, the same milestone.

Keep `overrides_applied: 0`. This is the single operator-ratifiable judgment (Open Question 1).

### Pitfall 2: gate reports 17 checks at `ea2770f` but 18 at HEAD
This is not drift. Phase 24 (commits `1266279`, `07c74e2`) added ANONYMOUS-DEFAULT (check 18) and rewrote check 8 into ANONYMOUS-VALUE-PRESENT. The script header says the count is a literal that moves in three places. Report both numbers and explain them.

### Pitfall 3: live `/repositories` lists 11 repos, not 4
Nexus ships built-in `maven-releases`, `maven-snapshots`, `maven-central`, `maven-public`, `nuget-hosted`, `nuget.org-proxy` and `nuget-group`. **Select the four chart names**; do not count the list. Their presence is not a chart defect. `config.enabled: false` (CONFIG-DISABLED) means the chart does not manage the Nexus defaults.

### Pitfall 4: the default StorageClass is literally *named* `default`
`STORAGECLASS default` in `kubectl get pvc` can be misread as "unset/default placeholder". It is a real class `default (default)` (provisioner `csi.trident.qnap.io`). Pair the PVC read with the STS template read (N3-g) and the `get storageclass` read so the mechanism is unambiguous.

### Pitfall 5: anonymous listing works live, but the chart default is closed
N1-g's unauthenticated `GET /repositories` succeeds because the **overlay** opts into NEXUS-02 (`anonymous.enabled: true` for the homelab). The chart ships `anonymous.enabled: false` (ANONYMOUS-DEFAULT). Do not describe the live anonymous read as chart-default behavior. If anonymous is ever turned off on the homelab, N1-g needs admin credentials. Do **not** add a credential to fix that. Cite 25-VERIFICATION instead.

### Pitfall 6: GSD tooling false negatives (tooling fit, not defects)
- **`gsd-sdk query frontmatter.get <plan> --field must_haves` returns `{"error":"Field not found","field":"--field"}`.** The positional form works (`frontmatter.get <plan> must_haves`), but it returns the object **nested** under `.must_haves` (`jq '.must_haves.truths'`). A naive `jq '.truths'` yields 0 and makes it look as if the plans have no must-haves. Measured: 35 truths across the 8 plans (4+4+5+5+3+5+5+4). The workflow text in `verify-phase.md` shows the `--field` form.
- `roadmap.get-phase 23` → `"success_criteria": []`. Must-haves therefore come from plan frontmatter (Option A), not ROADMAP (Option B). This is the same situation 25-VERIFICATION documented.
- `verify.key-links` false negatives on 23-02, 23-03 and 23-07. Each pattern is double-escaped (`\\.`), so it demands a literal backslash. Manual greps pass:
  - `nexus-live-smoke.sh:54` `PROVISION_SH="kubernetes/nexus/files/provision.sh"`;
  - `Chart.yaml:8` `version: 5.26.0`;
  - `docs/adr/README.md:30` links `adr020-nexus-chart-base-and-eula-opt-in.md`.
- `verify.key-links` on 23-08 reports "Source file not found", because the link is branch → branch (a remote fact). Substitute N1-b, as 19/20.1 did.
- `verify.artifacts` on 23-07: ADR-020 has 48 lines against `min_lines: 60`, but it is **19,622 bytes** with 4 sections (Context, Decision, Consequences, What was NOT verified), written as long one-line paragraphs. 23-07-SUMMARY:106 records "47 content lines". This is substantive, not a stub. ADRs are append-only, so there is **no fix**; record it as tooling-fit.
- On 23-06/23-08, `verify.artifacts` → "No must_haves.artifacts found". These are run/merge plans with no file artifacts, by design.

Record these in the VERIFICATION's Probe Execution section, and as new tooling findings in a `29.1-.../deferred-items.md` (not Phase 23's ledger).

### Pitfall 7: a fresh clone's gate exits 2, not 0
`kubernetes/*/charts/*.tgz` is gitignored, so a fresh clone gets `PREFLIGHT FAIL: subchart not vendored` → exit 2, which is an infrastructure state, not a defect. The v3.0 audit's integration pass saw exactly this "preflight-SKIP". The local clone already has the tgz, and P-b proves it is the genuine upstream artifact. For the `ea2770f` archive, copy the same tgz (valid because `Chart.lock` is identical between the SHAs).

### Pitfall 8: `-` sentinel is not an override
`--set nexus3.persistence.storageClass=-` renders `storageClassName: ""` (N3-d), which **disables** dynamic provisioning. Do not list it as override evidence. Mention it as a documented upstream behavior the chart README/values warn about.

### Anti-Patterns to Avoid
- **Any mutation.** No `helm install/upgrade` on the homelab, no `kubectl apply/delete/patch`, no ArgoCD sync, no pushes or PRs to `security-platform` or the overlay, and no edits to `repos/security-platform` (mutation tests run in `$S`, never in the clone).
- **Editing the overlay working tree or reading it instead of `origin/main`.** It has an unrelated ` M CLAUDE.md`; always use `git show origin/main:<path>`.
- **Copying SUMMARY prose into Evidence cells** (P-01). Every cell must hold a command and its observed output.
- **Leaving port-forwards running.** Start in background, record the PID, and `kill` it in the same task (25 precedent).
- **Editing ADR-020** to satisfy `min_lines`. ADRs are append-only (CLAUDE.md).
- **Counting as proof** (STATE.md lesson): verify *which* members, not just how many (Pitfall 3).

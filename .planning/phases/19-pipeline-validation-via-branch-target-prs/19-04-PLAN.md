<objective>
Trace one seeded finding — the `eval()` call in `fixtures/vulnerable.py` (D-08) — through all three hops
Success Criterion 3 asks for: the source file, the Security tab entry, and the retained JSON artifact. Then
put the alert's own page in front of a human so the "Security tab entry" half is observed rather than
inferred.

Purpose: SC3's wording is "traced from its source file through to BOTH the Security tab entry AND the
retained JSON artifact". Phase 17 scored the equivalent criterion NOT OBSERVED for offering API evidence
where a UI observation was asked for, and 17-07 established the standing rule that a criterion whose only
evidence path is a UI observation gets NOT OBSERVED with a named cause rather than a MET inferred from the
API. RESEARCH Q2 recommends foreclosing that outcome cheaply: capture the API evidence in full AND ask a
human one yes/no question about one URL that is already known to render. D-08 makes this the NEW SAST
fixture specifically, which also closes the gap that Phase 17 never traced a SAST finding through to the
Security tab.

Output: a three-hop trace table with the alert number, rule id, path, line and `html_url`, the matching
artifact entry, and the operator's reply recorded verbatim.

Sequencing note: waves are strictly sequential. This plan runs BEFORE the gate flip because plan 05's empty
commits create new runs and new analyses; tracing against the clean report-only baseline keeps the evidence
unambiguous. Do not push anything, do not merge, do not close the PR.
</objective>

<notes>
**Use the ref filter. Never the bare Security tab.** An unfiltered read returns `[]` every time and would be
recorded as a failure or, worse, "fixed" by reversing ADR-016.

**Hand the human ONE url and ONE yes/no question.** Not "check the Security tab". That open-ended ask is
what cost Phase 17 a criterion, and the `html_url` is a single-click page already proven to render.

**Do not push, merge or close.** Plan 05 owns the next runs; plan 07 owns the PR's fate.

**The alert may take a moment to appear.** `upload-sarif` runs with `wait-for-processing` at its default
`true`, so a completed run means ingestion completed — but if the alerts query returns nothing, re-query
before concluding anything, and if it is still empty, STOP and report rather than substituting a different
finding or a different tool.

**Scratch downloads go under `$SCRATCH`**, never `/tmp` and never inside either repository.
</notes>

## Shared Patterns

### PASS/FAIL line discipline (all scripts)
- Gate: `fail(label, message)` collects `FAIL: <LABEL>: <msg>` and ends `FAILED - n check(s)` with exit 1 or `PASS - N checks, 0 failures` (check-workflow-uploads L160-164, L723-730). Exit 2 is reserved for preflight (L82-86).
- Lifecycle: `pass` / `fail` / `abort` print `==> <ID>: PASS|FAIL - <detail>`. `print_summary` refuses a zero-check pass ("NOTHING RAN") (L417-459).
- Proof: `proof_pass` / `proof_fail` / `proof_skip` / `proof_abort` print `PROOF: <ID> PASS|FAIL|SKIP <detail>`. A skip is never counted (L392-423).
- **No vacuous pass anywhere.** Each new check needs an explicit count > 0 clause (D-08 zero overlap; P-IMAGE-TAG count > 0 and == ci/main count).

### Project rules (all new or edited scripts and evidence)
- No executable bit. Invoke as `bash scripts/<name>.sh`. Headers say so (check-workflow-uploads L71-72, lifecycle L22-23, import-proof L129-132).
- On any live failure (429 on the base-image pull, a dispatch head-SHA mismatch, old ids staying active in D-14.1): STOP, report the raw output with a theory and a proposal, and WAIT. No silent rerun.
- Push, PR, merge, tag and `workflow_dispatch` each need operator approval, then an `origin/main` readback.

### API access (lifecycle / proof)
- Lifecycle: one curl call site through `api_transport` / `api_get_all` (ADR-029). Filter guards check client-side that every row belongs to the requested parent (L612-628).
- Proof: dedup.py `get` / `get_all` (L1696-1740), with `-q` first and a `ssl_verify_result` check.
- Do not add new curl code in either script.

### Docs follow evidence
- PR A carries code, gate, proof and assertion. PR B carries TRIAGE/README text only after the D-08 live PASS. ADR-031 and its index row come after the tag (D-18). This follows the 29-18 PR B pattern.

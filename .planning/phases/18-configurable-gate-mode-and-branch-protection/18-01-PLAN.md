<notes>
**Never add a sixth job.** 18-RESEARCH Pattern 5 and `check-workflow-uploads.sh` check 10 agree: the
validation is a step inside each of the five jobs. A sixth job would emit a sixth `security / …` check
run, break CICD-01's five-parallel-jobs shape and change the frozen required-check set.

**Do not touch the eleven ADR-001 `continue-on-error: true` lines** (L60, 124, 197, 244, 379, 616, 671,
755, 805, 885, 932). ADR-001 is Accepted and append-only.

**Do not declare `default:` on the input.** A `workflow_call` string input with no default is `""`, which
is falsy, which is what lets the `||` chain reach `vars.GATE_MODE`. `default: report-only` makes
`inputs.gate_mode` always truthy and silently kills the copy-paste consumption mode (Criterion 2).

**PyYAML parses the bare `on:` key as the boolean `True`, not the string `"on"`.** Index it as
`doc.get(True) or doc.get("on")`. Already recorded at the top of `scripts/check-workflow-uploads.sh`.

**Commit with explicit `--files`/pathspec arguments.** The outer docs repo carries ~100 unrelated
uncommitted `.claude/` changes; a bare `git add -A` is wrong in either repo. Diff verification uses
`git diff HEAD~1 HEAD`, never `git diff HEAD~1` (17-06 hit the working-tree form and got a false FAIL).
</notes>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Caller repository settings (`vars.GATE_MODE`) → called workflow | Untrusted-in-shape external input: a repo variable is a free-text string set outside this file's review |
| `workflow_call` caller YAML (`inputs.gate_mode`) → called workflow | Typed but unvalidated: GitHub checks the type, never the enum |
| Workflow source → local static gates | `actionlint` / `yamllint` / `check-workflow-uploads.sh` are the only pre-push arbiters of this change |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-18-01 | Tampering | `env.GATE_MODE` resolution chain | mitigate | Resolve once at workflow level so eleven expressions cannot diverge; `\|\|` chain ends in the literal `'report-only'` so an unset value is defined, never blank |
| T-18-02 | Spoofing | `gate_mode` as an unvalidated string (ASVS V5) | mitigate | `Validate gate_mode` case step in every job, intolerant and unguarded, rejecting the empty string and any non-enum value with the offending value echoed |
| T-18-03 | Denial of Service | A sixth "validate" job changing the frozen check-run set | mitigate | Validation is a step, never a job; `check-workflow-uploads.sh` check 10 (JOB-SHAPE) asserts exactly 5 jobs and the frozen names on every commit |
| T-18-09 | Tampering | The eleven ADR-001 upload tolerances | mitigate | Named as do-not-touch with line numbers; `grep -c 'continue-on-error: true .*ADR-001'` asserted at 11; the offline gate independently fails if any upload step loses `continue-on-error: true` |
| T-18-13 | Repudiation | A live run whose effective mode cannot be told from its log | mitigate | The accepted branch echoes `gate_mode=<value>`; 18-04/18-05 read it back as evidence rather than inferring the mode |
| T-18-SC | Tampering | npm/pip/cargo installs | accept | No package is installed by this phase; only `git`, `actionlint`, `yamllint`, `python3` run |

<notes>
**Merge only on an explicit human instruction.** Task 1 is a blocking checkpoint. Do not merge on an
inferred approval, a thumbs-up on something else, or silence.

**Verify from the remote.** `git fetch origin` then `git show origin/main:<path>`. A local working tree is
not evidence of what is on `main`.

**A criterion that was not observed is recorded as NOT OBSERVED, with what was observed instead.** Do not
upgrade static validation into a live observation. 16-07 and 17-05 both did this correctly and it is the
standard here.

**Do not mark a requirement complete before the post-merge read.** 17-01 flipped two requirements early
and had to revert them. Mark CICD-04 and CICD-06 in this plan, after Task 2's verification, and not
before.

**Leave nothing set.** Confirm once more that `GATE_MODE` does not exist as a repository variable and that
`rules/branches/main` is in the state 18-05's operator decision left it.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Phase branch → `main` of the reference implementation | An irreversible publication; everything downstream copies from `main` |
| Local working tree → claims about `main` | The local checkout has been on a different branch with a stale `main` throughout this milestone |
| Criterion verdicts → the project's record of truth | A rounded-up verdict silently removes a gap from the roadmap |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-18-25 | Tampering | Merging without explicit human instruction | mitigate | Blocking `checkpoint:human-verify` with a literal resume phrase; the merge command sits in the following task and runs only after it |
| T-18-26 | Repudiation | Asserting what is on `main` from the local tree | mitigate | `git fetch` then `git show origin/main:<path>` for every assertion; the local tree is never the evidence |
| T-18-22 | Repudiation | Scoring a statically-validated behaviour as live-observed | mitigate | Criterion 2's two halves scored separately; NOT OBSERVED required in those words where applicable |
| T-18-17 | Denial of Service | A leftover `GATE_MODE` variable or an unintended ruleset change surviving the phase | mitigate | Both read back after the merge and reported; the expected state is the operator's recorded 18-05 decision |
| T-18-27 | Tampering | Requirements marked complete before the post-merge read (the 17-01 failure) | mitigate | Marking happens in Task 2 after verification, and the ordering is an acceptance criterion |
| T-18-SC | Tampering | npm/pip/cargo installs | accept | No package installed; `git`, `gh`, `actionlint`, `yamllint`, `python3` only |

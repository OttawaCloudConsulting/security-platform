# Phase 29.6 Plan 04: Race Driver Summary

This plan adds `29.6-race.sh`, the operator-run race driver for the closed-PR reopen race. It follows the plan-03 contract. Before any write it runs the D-18 pre-close guard. It then closes the PR, waits for the close run in variant a, reopens, makes the single D-19 `gh pr view` read, and merges only with `gh pr merge --squash --match-head-commit`. After that it writes the attempt dir and hands it to `29.6-verdict.sh`. It was rehearsed offline in dry-run for both variants. No live GitHub read or write was made.

## What was built

- **Header** (22-04 shape): it carries the do-not-chmod rule, a single absolute-path invocation, the reasons this is an operator script, nine numbered mitigations and the exit-code table (0/1/2/3/4/9). The header states:
  - The BLOCKED guard runs only before the close (the 22-04 guard inverted).
  - The D-19 read overrides research Pattern 5.
  - The D-07 deviation: no check-runs read between reopen and merge (ADR-033 cites this).
  - The admin-bypass, auto-merge and delete-branch flags are never passed. Their literals appear nowhere in the file, comments included.
- **Pre-close guard (exit 1, nothing written).** Reads, in this order:
  1. race-target `.proceed == true`.
  2. The ruleset file named by `.ruleset_created_file`. It must be one of the two 29.6-07 names and must have a numeric `.id`.
  3. `29.6-05-contexts.json`, which must hold exactly five strings.
  4. `GATE_MODE` is `blocking`.
  5. `required_status_checks` is on main.
  6. `bypass_actors == []` and `current_user_can_bypass == never`.
  7. The PR is OPEN with a 40-hex head SHA.
  8. The five newest check runs are completed and at least one failed.
  9. `settle_merge_state` returns BLOCKED.
- **Race.** Close (rc captured). Variant a then polls `close_run_detect` (2 s, 60 reads); a timeout exits 3 and leaves the PR CLOSED, never reopened. Variant a also takes the pre-reopen snap. Then reopen, one timestamped `gh pr view --json mergeStateStatus,mergeable,headRefOid`, and the merge with stdout and stderr in separate files. No meta write and no check-runs read happen inside the window. After the window come the post-merge snap, `pr-after.json`, and settle snaps every 3 s up to 120 times; a timeout is recorded as `settle_timeout` and is not fatal. Then the final snap, `checkruns-final.json`, `runs.json`, `pr-timeline.json` (`--paginate --slurp` then `jq add`) and the verdict. Exit 9 prints the D-11 banner and stops. Any other non-zero verdict stops with that code.
- **meta.json** holds every contract key with numeric `pr` and rc values. It also holds `ruleset_id`, `ruleset_created_file`, `rule_types_main`, `pre_close_settled_merge_state`, `pre_suites`, `detect`, `t_premerge_read_end`, `settle_timeout` and `t_final_dumps`. It is rewritten after each step outside the window, so the exit-2 and exit-3 paths leave a record.
- **Error handling.** `set -E` plus an ERR trap maps unexpected failures to exit 2. Commands expected to fail use the `29.6-pr.sh` idiom (`trap - ERR; set +e; ...; rc=$?; set -e; trap ... ERR`). A harness confirmed that `if out=$(f)`, `if f >file` and `f || rc=$?` all leave the trap silent when `f` returns 1.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 2 - Correctness] Attempt dir created after the guard, not before it**
- **Found during:** Task 1 design
- **Issue:** The plan's step 1 creates the dir, then runs the preconditions. An exit 1 would leave a dir with no verdict. That burns the label, and plan 11 requires `verdict.json` in every `29.6-race-*` dir.
- **Fix:** Order is now: refuse if the dir exists, run every guard read, `mkdir`, then the pre-close snap.
- **Commit:** f876ab6

**2. [Rule 2 - Safety] gh tripwire inside the script's dry-run branch**
- **Issue:** The plan says dry-run makes no GitHub calls. Plan 02's incident showed that intent alone is not enough.
- **Fix:** Under `--dry-run`, gh is redefined as a function that prints `TRIPWIRE(2)` and exits 2.
- **Commit:** f876ab6

### Additions within plan scope

- The rehearsal also covers more than three attempts (exit 2) and duplicate labels or PRs (exit 2).
- There is a stubbed live-path supplement section. The plan only required dry-run.

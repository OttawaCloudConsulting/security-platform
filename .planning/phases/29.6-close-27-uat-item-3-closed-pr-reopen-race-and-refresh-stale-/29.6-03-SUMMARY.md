## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Context-name derivation scoped to the opened run**
- **Found during:** Task 1
- **Issue:** The plan said to build the five names "excluding names containing DefectDojo". PR #21's head has two workflows (`scans / …` and `security / …`) plus `prove-import`, so that filter gives 10+ names and the newest_per_context case could not reach 5.
- **Fix:** The self-test now keeps only check runs whose run id is the opened run 36156728417, then removes DefectDojo. The names are still read live and never typed.
- **Commit:** 7ee2c51

**2. [Rule 1 - Bug] Detector evaluates every new-suite candidate**
- **Found during:** Task 1 (from live data)
- **Issue:** With PRE=[opened suite], two suites are "new": the close suite and the `scans` workflow suite 97914681376. Both are completed. Checking only one candidate could pick the wrong suite.
- **Fix:** `close_run_detect` checks every completed candidate, newest first, and reports detection only for a candidate that owns all five contexts' newest check runs.
- **Commit:** 5dc86ce

**3. [Rule 2 - Correctness] verdict.json written only to a private copy during self-test**
- **Issue:** `verdict.sh` writes `verdict.json` into the attempt directory, which would dirty the committed fixtures.
- **Fix:** The self-test copies each fixture to a temp directory before running the verdict on it.
- **Commit:** 07eaff0

### Additions within plan scope

- `29.6-fixtures/build-fixtures.py` regenerates every fixture, so the synthetic ids can be checked and rebuilt.
- Each fixture also carries `pr-timeline.json` from the attempt-dir contract. The verdict does not require it.
- Precedence of the verdict rules is fixed in the script header and shown in `reason`. The plan did not specify an order.

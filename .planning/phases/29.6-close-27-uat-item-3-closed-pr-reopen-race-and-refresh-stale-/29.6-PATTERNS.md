### `29.6-race.sh` (operator script, live request-response + polling)

**Primary analog:** `$P22/22-04-operator-merge-attempt.sh` (154 lines)
**Secondary:** `$P22/22-poll-merge-state.sh` (107 lines), `$P22/22-02-operator-gate-window.sh` (286 lines)
**Header conventions also seen in:** `.planning/phases/29.4-…/29.4-replay-d09.sh` L1-30, `.planning/phases/29.5-…/29.5-ci-main-verified-diff.sh` L1-44

**Header block** (22-04 L1-46). Copy the shape: shebang, `set -euo pipefail`, name and plan/task line, `NEVER set the executable bit`, a single absolute-path `bash` invocation, a WHY paragraph, the list of numbered mitigations, an operator warning about `--auto`, and an exit-code table:
```bash
#!/usr/bin/env bash
set -euo pipefail

# 22-04-operator-merge-attempt.sh — Phase 22 plan 04, Task 1: attempt the merge
# and capture GitHub's refusal verbatim.
#
# NEVER set this file's executable bit. Run it as:
#
#   bash /Users/christian/.../22-04-operator-merge-attempt.sh
#
# One absolute-path invocation, deliberately: plan 03's command 2 was first
# pasted as a multi-line continuation, the shell failed to parse the wrap and
# returned 127, and the script never ran. A single token cannot line-wrap.
...
#   3. --admin is NEVER passed (it exists to bypass the very gate being
#      witnessed); neither is --auto, see the warning below
#   4. stderr redirected into stdout and tee'd — the refusal arrives on stderr
#      and it IS the deliverable
...
# Exit codes:
#   0  the merge was REFUSED and every post-assertion held — the expected path
#   1  a precondition failed; nothing was attempted
#   9  THE MERGE SUCCEEDED — see the banner this prints. Not recoverable here.
```
For 29.6, the exit-9 banner maps to **race lost → D-11 STOP**. Exit 0 maps to **blocked**. Add the D-19 client-side/server-side classification to the stdout record.

**Precondition reads** (22-04 L62-95). Rule types from `rules/branches/main`, `main` HEAD unchanged, and a fresh `mergeStateStatus` read:
```bash
RULES=$(gh api "repos/${REPO}/rules/branches/main" --jq '[.[].type]|sort|join(",")')
case "$RULES" in
  *required_status_checks*) echo "  ok: required_status_checks is still in force" ;;
  *) echo "ABORT(1): required_status_checks is NOT on main. ..."; exit 1 ;;
esac
...
S=$(gh pr view "$PR" -R "$REPO" --json mergeStateStatus --jq .mergeStateStatus)
if [ "$S" != "BLOCKED" ]; then
  echo "ABORT(1): mergeStateStatus is '${S}', not BLOCKED — refusing to run gh pr merge."
  exit 1
fi
```
**29.6 deviation (must be explicit in the plan):** the `BLOCKED` assertion belongs **before `gh pr close`**. That is the D-18 red-SHA precondition (RESEARCH Pitfall 1). It must **not** run between reopen and merge. After reopen the state is expected to be `UNKNOWN` or stale, and the merge into that unsettled state is the measurement. Also add `current_user_can_bypass == "never"` to the preconditions (RESEARCH Pattern 3, ADR-019 L12).

**Attempt with verbatim capture** (22-04 L102-112). `errexit` is lifted only around the attempt, the rc is taken from `PIPESTATUS`, and there is no `|| true`:
```bash
set +e
gh pr merge "$PR" -R "$REPO" --squash 2>&1 | tee "$ATT"
RC=${PIPESTATUS[0]}
set -e
printf '%s\n' "$RC" > "$RCF"
```
For 29.6, capture stdout and stderr **separately** so the D-19 classification has clean input. ADR-019 L20 records that a combined paste lost the separate stderr. Use `2> "$ERR"` plus `tee` on stdout. Do not take a full `snap` between `gh pr reopen` and `gh pr merge` in variant (b) (RESEARCH Pattern 5). Record only python3 ISO-ms timestamps around the two commands.

**Post-assertions from fresh reads** (22-04 L114-150). After the attempt, read `state,mergedAt` and `main` HEAD again. If the PR is merged, print the banner and exit 9. If rc is 0 but nothing merged, exit 9 as an anomaly:
```bash
gh pr view "$PR" -R "$REPO" --json state,mergedAt > "$PRAFTER"
...
if [ "$STATE_AFTER" = "MERGED" ] || [ "$MERGED_AT" != "None" ]; then
  echo "## THE MERGE SUCCEEDED. THE GATE DID NOT HOLD.                        ##"
  echo "## STOP. Do not run anything else. Report this immediately.           ##"
  exit 9
fi
```

**Bounded settle-poll** (22-poll-merge-state.sh L61-107). Use it for the pre-close `BLOCKED` read and for the reads after each attempt. The key rule is the two-condition post-loop guard (not `UNKNOWN` **and** different from the previous value), with exit 2 for a `gh` failure and no fallback value:
```bash
if [ "$S" != "UNKNOWN" ] && [ "$S" != "$PREV" ]; then
  printf '%s\n' "$S"
  exit 0
fi
```
The script also takes `POLL_ITERATIONS`/`POLL_SLEEP` from the environment (L71-72), so its failure paths can be tested cheaply. The variant-(a) close-run detector should do the same.

**Run wait and check-runs dump** (22-02 L176-200). Poll with a bound for a run on the new head SHA, then dump the check runs filtered by `app.id`:
```bash
for i in $(seq 1 30); do
  RUNID=$(gh run list -R "$REPO" --branch "$BRANCH" \
            --json databaseId,status,conclusion,headSha \
            --jq "[.[] | select(.headSha == \"${NEWSHA}\") | select(.databaseId != ${BASELINE_RUN})] | first | .databaseId // empty")
  if [ -n "$RUNID" ]; then echo "run appeared: ${RUNID} (poll ${i}/30)"; break; fi
  sleep 5
done
[ -n "$RUNID" ] || { echo "ABORT(1): no workflow run appeared for ${NEWSHA} after ~145s." >&2; exit 1; }
```
**29.6 deviation:** do not gate on run `status` alone. Run 36158851741 reported `completed` 6 s before its last check run's `started_at` (RESEARCH Pitfall 3). Use RESEARCH Pattern 5's detector instead: five names, newest by `id`, all `skipped`, with suite equal to the close run's `check_suite_id`. Use `check-runs?filter=all` and never `filter=latest` (RESEARCH anti-patterns).

**Paths and scratch** (22-02 L35-46). Constants at the top: `REPO`, `PR`, `APP_ID=15368`, an absolute evidence dir, and a clone in the session scratchpad ("Temp files live in the session scratchpad, never /tmp (project rule)"). 22-04 L58 runs `cd "$PHASE_DIR"   # explicitly NOT the exercise clone; every call is -R scoped`. Copy that, and pass `-R` on every `gh` call.

### Enforcement-proof and gate-window operator script(s) (D-04/D-05/D-20)

**Analog:** `$P22/22-02-operator-gate-window.sh`
**Why one script** (L10-18): a repository-wide `GATE_MODE` flip is set, measured and closed in one machine-bounded run with an EXIT trap. **29.6 difference:** in 29.6 `GATE_MODE=blocking` stays set across all race attempts (D-18) on a throwaway repo, so the window does not have to be minutes long. The planner can drop the closing trap and record that it was dropped on purpose, or keep it scoped to the enforcement proof.

**Guard-then-act trap** (L84-100), never `|| true`:
```bash
close_window() {
  if [ "$WINDOW_CLOSED" -eq 1 ]; then return 0; fi
  if gh variable list -R "$REPO" --json name --jq '.[].name' | grep -qx GATE_MODE; then
    if gh variable delete GATE_MODE -R "$REPO"; then
      echo "GATE_MODE deleted."
    else
      echo "!!! GATE_MODE DELETE FAILED. THE REPOSITORY IS STILL BLOCKING. !!!" >&2
```
**Server-side timestamp for the window** (L139-140): `gh api "repos/${REPO}/actions/variables/GATE_MODE" --jq '.created_at'`.
**Retrigger by empty commit, not `gh run rerun`** (L148-156). The reason given: upload-artifact v4 needs unique artifact names per run. Reuse this for the PR-0 `UNSTABLE` step.
**Mode proven from the run's own logs** (L203-215): `gh run view "$RUNID" --log`, then keep only the `gate_mode=` lines in evidence. This is the RESEARCH Pattern 2 check that Mode B `vars.GATE_MODE` reached the callee.

**Ruleset write:** `repos/security-platform/scripts/set-required-checks.sh` (header L4-40). It is a dry run by default. `--apply` requires `--verify-sha` and `--yes-i-understand-lockout`. The required ordering is green in report-only, then red under blocking, then apply (L29-33):
```bash
# ORDERING (D-07): confirm the five checks appear GREEN in report-only mode
# first, then flip `gh variable set GATE_MODE --body blocking` and observe
# them go RED, and only THEN run this script with --apply to make them
# required.
```
The script is PUT-only, so the create step is a raw `POST` (RESEARCH Pattern 3 step 1). Tell the operator that the script's lockout banner names `security-platform` and can be ignored here (RESEARCH Pattern 3).

29.6-snap.sh — sourceable (`source 29.6-snap.sh` defines functions, no side effects) and CLI (`bash 29.6-snap.sh <fn> <args>`). GET-only. APP_ID=15368. Every function exits 2 on a gh failure (no fallback value).
- iso_now -> ISO 8601 UTC with milliseconds from python3 (never `date`).
- checkruns_all R SHA -> JSON array, all check runs with app.id==15368: {name,id,status,conclusion,suite:.check_suite.id,run:(details_url "runs/<n>" capture),started_at,completed_at}. Uses `repos/R/commits/SHA/check-runs?filter=all&per_page=100`; exits 2 if total_count > 100.
- newest_per_context R SHA CONTEXTS_JSON -> array, one entry per name in CONTEXTS_JSON (a JSON array of the five names): max_by(.id) of that name; a missing name yields {name, missing:true}.
- pr_state R PR -> {state,mergeStateStatus,mergeable,headRefOid} from `gh pr view`.
- runs_for_sha R SHA -> [{id,created_at,status,conclusion,check_suite_id,event,run_attempt}] from `repos/R/actions/runs?event=pull_request&head_sha=SHA&per_page=100`, ALSO filtered client-side on head_sha (research A8; security-platform has far more than 50 PR runs since 2026-09-25, so an unfiltered page would miss run 36158851741). If the server ignores head_sha (client filter finds none on page 1 while total_count > 100), fall back to `--paginate` capped at 10 pages and exit 2 beyond that. The live self-test doubles as the A8 check.
- settle_merge_state R PR PREV -> polls pr_state every POLL_SLEEP s (default 3) up to POLL_ITERATIONS (default 20) until mergeStateStatus != UNKNOWN and (PREV empty or != PREV); prints the value; exit 3 on timeout.
- close_run_detect R SHA PRE_SUITES_JSON CONTEXTS_JSON -> prints {detected,run_id,suite,run_status,run_conclusion,newest:[...]}; PRE_SUITES_JSON is the JSON array of check-suite ids present on SHA before the close (from the pre-close snap), so no local timestamp is compared with server time. Exit 0 when a run from runs_for_sha whose check_suite_id is NOT in PRE_SUITES has status completed AND every context's newest-by-id check run has suite == that run's check_suite_id and status completed; exit 1 when not yet; exit 2 on error. It records conclusions (skipped expected; cancelled tolerated and recorded, never asserted away).
- snap LABEL (env R, PR, SHA, CONTEXTS_JSON) -> one compact JSON line {label, ts, pr: pr_state, check_runs: checkruns_all, newest: newest_per_context}.

Attempt directory contract (written by 29.6-race.sh, read by 29.6-verdict.sh): evidence/29.6-race-<label>/
- meta.json {label, variant ("a"|"b"), repo, pr, head_sha, contexts[5], gate_mode, current_user_can_bypass, bypass_actors, t_close, t_detect (a only), t_reopen_start, t_reopen_end, t_premerge_read, premerge_state {mergeStateStatus,mergeable,headRefOid}, t_merge_start, t_merge_end, close_rc, reopen_rc, merge_rc}
- timeline.jsonl (snap lines; labels: pre-close, pre-reopen (variant a only), post-merge, settle-<n>, final)
- merge-stdout.txt, merge-stderr.txt (separate), checkruns-final.json (checkruns_all), runs.json (runs_for_sha), pr-after.json {state,mergedAt,mergeCommit,headRefOid}, pr-timeline.json

29.6-verdict.sh:
- `bash 29.6-verdict.sh <attempt-dir>` -> writes <attempt-dir>/verdict.json and prints it. Exit 0 blocked, 9 lost, 1 invalid, 4 anomaly, 2 usage/missing file.
- `bash 29.6-verdict.sh --classify-stderr <file>` -> prints client-side | server-side | unclassified.
verdict.json keys: label, variant, pr, head_sha, precondition_red, variant_a_precondition (bool or null), gate_mode, current_user_can_bypass, merge_rc, merged, refusal_source, refusal_line, close_suite, reopen_suite, close_suite_conclusions, reopen_contexts_at_post_merge [{name,status,conclusion,suite}], reopen_complete_at_post_merge, verdict, reason.
Rules (D-10 amended by D-18, D-19):
- precondition_red = pre-close snap pr.mergeStateStatus == "BLOCKED" AND all five newest completed AND >= 1 newest conclusion == "failure".
- variant_a_precondition (a only) = in the pre-reopen snap every context's newest has suite == close_suite and status completed.
- Suite attribution by SET DIFFERENCE, never by timestamps (research Pitfalls 3/4; local clock skew would flip attribution in variant b): new_suites = suite ids present in checkruns-final.json (five contexts) but absent from the pre-close snap's check_runs. close_suite = the new suite whose five check runs are all skipped or cancelled; reopen_suite = the other new suite. Exactly two new suites are expected; any other count is anomaly. runs.json is corroboration only (record whether its check_suite_ids agree; a disagreement is recorded in reason, not used for attribution).
- merged = merge_rc == 0 OR pr-after.state == "MERGED".
- invalid if NOT precondition_red, or gate_mode != "blocking", or current_user_can_bypass != "never", or (variant a and NOT variant_a_precondition).
- anomaly if merge_rc == 0 and state != MERGED, or merge_rc != 0 and state == MERGED.
- lost if merged and precondition_red and at post-merge snap any context's newest is not from reopen_suite or not completed (D-18 definition); merged with the reopen suite already complete is anomaly (enforcement failure, still STOP).
- blocked if not merged and merge_rc != 0.
- refusal_source (only when not merged): client-side if stderr matches `base branch policy prohibits the merge` or `is not up to date with the base branch` or `merge commit cannot be cleanly created`; server-side if stderr matches (case-insensitive) `GraphQL` or `HTTP 4[0-9][0-9]` or `Repository rule violation` or `required status check`; else unclassified. refusal_line = first matching stderr line verbatim.

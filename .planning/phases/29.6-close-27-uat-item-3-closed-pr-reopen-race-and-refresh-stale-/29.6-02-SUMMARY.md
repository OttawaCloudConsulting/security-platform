# Phase 29.6 Plan 02: Scratch Test Bed Seed and Operator Scripts Summary

This plan adds the seed files for the `OttawaCloudConsulting/sp-reopen-race-scratch` repo and the two operator-run write scripts. The seed is a Mode B caller copied byte-for-byte from the adoption guide, an alpine 3.20 Dockerfile pinned by digest to public.ecr.aws, and a ruleset body with no bypass actors. The scripts are `29.6-bootstrap.sh` and `29.6-pr.sh` (subcommands `open`, `empty-commit`, `merge-attempt`). Both stop before writing if a check fails, both have a dry-run mode, and both were rehearsed offline. No GitHub write was made.

## What was built

- **pr-security.yml**: `diff <(sed -n 169,218p docs/adoption-guide.md)` is empty. It uses `security.yml@v1`, `types: [opened, synchronize, reopened, closed]`, and has no `with:` block (D-02). No DefectDojo variable is set anywhere (D-03).
- **Dockerfile**: `FROM public.ecr.aws/docker/library/alpine:3.20@sha256:d9e853e8...b6bc`, `RUN echo ok > /ok.txt`, `CMD ["cat", "/ok.txt"]`. There is deliberately no USER or HEALTHCHECK (D-05, RESEARCH A2 ASSUMED). The digest comes from a live anonymous-token HEAD request to public.ecr.aws, recorded in `evidence/29.6-02-base-digest.txt`.
- **ruleset-default.json**: Default, branch, active, `~DEFAULT_BRANCH`, `bypass_actors: []`, with the rules deletion and non_fast_forward.
- **29.6-bootstrap.sh**: checks run in this order, all before any write:
  1. The clone directory and its parent resolve (realpath) outside the planning repo.
  2. The clone directory does not exist.
  3. The seed files are present.
  4. The gh login is OttawaCloudConsulting and the account type is User (D-20).
  5. `gh api repos/$REPO` fails with a clean HTTP 404.

  It then creates the repo with `--private` (D-04), runs git init, copies the seed in, commits, and adds origin. It asserts `remote get-url origin` equals the scratch URL before the push, then reads the repo back. The two offline checks run before any gh call, so a clone directory inside the planning repo gets exit 1 even with no network.
- **29.6-pr.sh**: follows the interface contract exactly. `assert_clone` (realpath outside the planning repo, `.git` present, origin equals the scratch URL) runs before every push. Labels are restricted to `[A-Za-z0-9._-]+`. Timestamps come only from python3 at millisecond precision. JSONL lines are built with `json.dumps`. `merge-attempt` uses `--squash --match-head-commit`, writes separate `-stdout.txt`, `-stderr.txt`, `-rc.txt` and `-pr-after.json` files, and makes no gh calls under `--dry-run`.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] Trailing whitespace stripped from base-digest evidence**
- **Found during:** Task 1 commit
- **Issue:** The pre-commit hook rejected the trailing space on the raw `HTTP/2 200 ` header line.
- **Fix:** Removed trailing whitespace from the lines. The header content is otherwise verbatim. The rehearsal transcript got the same treatment.
- **Commit:** 6f71c27

**2. [Rule 1 - Bug] `set -E` added to both scripts**
- **Found during:** Task 2
- **Issue:** Bash does not run an ERR trap inside functions unless errtrace is on. Without it, a gh/git failure inside `run_write` or `cmd_*` would exit with the command's own rc, for example 1, which collides with the precondition exit code.
- **Fix:** Added `set -E` below the required `set -euo pipefail`. Rehearsal section 8 confirms the failure now exits 2.
- **Commit:** ea70199

### Process incident (no write occurred)

**3. Real `gh pr merge` was called 4 times during the rehearsal**
- The first try at the outcome matrix (section 9) used a gh stub on PATH. The stub was deliberately left non-executable under the project's no-exec-bit rule, so PATH lookup skipped it and the real `gh` ran `gh pr merge 1 -R OttawaCloudConsulting/sp-reopen-race-scratch --squash --match-head-commit deadbeef` 4 times.
- The scratch repo does not exist (it returned a clean 404 in section 4). Every call failed at repository resolution (`GraphQL: Could not resolve to a Repository`, rc 1) before any mutation, so **nothing was written**.
- The plan said the rehearsal would be offline/dry-run only, and these 4 calls were not. The transcript is kept as-is with an INCIDENT NOTE above it.
- The matrix was then re-run (section 9b) with an exported bash function stub. Before running, it checked that `type gh` reported a function, and it ran with an empty `GH_CONFIG_DIR` and no token, so falling through to the real gh could not authenticate.
- Side effect: these runs showed the live infra-failure path (merge fails, then `gh pr view` fails, then exit 2). They also showed that the capture files are written before that exit, so a re-run needs a new `--out-prefix`.

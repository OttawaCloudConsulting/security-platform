## Implementation Decisions

### Test bed
- **D-01:** Run the race in a **new throwaway repository** in the `OttawaCloudConsulting` org. Do not add a temporary required-checks rule to `security-platform`, and do not settle for analysis only. The throwaway repo's ruleset on the default branch requires exactly the five contexts. Read the context names from a live check-runs listing, never retyped (adoption-guide §8):
  - `security / SAST — Semgrep CE`
  - `security / IaC — Checkov`
  - `security / SCA — Trivy Filesystem`
  - `security / Container — Trivy Image`
  - `security / Secrets — Gitleaks`
- **D-02:** The caller is **Mode B**: `uses: OttawaCloudConsulting/security-platform/.github/workflows/security.yml@v1` (today `v1` = `v1.4.0`). The `pr-security.yml` copy is the adoption-guide §5 caller with `types: [opened, synchronize, reopened, closed]`. Record the SHA that `v1` resolves to at run time in the evidence.
- **D-03:** **DefectDojo is off** in the throwaway repo: no `DEFECTDOJO_URL` and no `DEFECTDOJO_API_TOKEN`, so both DefectDojo jobs skip. The homelab instance and the ARC runner (ADR-028) are not involved.
- **D-04:** The repo is **private**. Research must confirm that rulesets with required status checks are enforced on a private repo in this org's plan. If they are not, fall back to **public** and record why. A ruleset that GitHub accepts but does not enforce would make every attempt look "blocked" or "merged" for the wrong reason, so enforcement must be proven first. Use the ADR-019 pattern: a red required check gives `BLOCKED` and `gh pr merge` is refused.
- **D-05:** Set `gate_mode` so that the precondition in D-04 can be shown. The scratch repo needs a commit that makes at least one required context red under `blocking`, or another way to prove the ruleset gates. Watch the self-lockout trap from adoption-guide §8 (`bypass_actors: []`). Every merge in this repo must stay possible, or the bypass/cleanup path must be clear before the contexts are required.
- **D-06:** **Delete the throwaway repo after the evidence is captured**, as its own operator-approved checkpoint. Repo deletion cannot be undone. Before the delete, save to `evidence/` the check-runs JSON per head SHA, the PR timeline/events, the run IDs and the merge responses. Run links in the ADR will go dead, so the evidence files must stand alone.

### Race procedure
- **D-07:** Drive the sequence with a **scripted tight loop**, a phase-local script run with `bash`. The script runs `gh pr close`, then `gh pr reopen`, then `gh pr merge`, back to back. At each step it logs an ISO timestamp, `mergeStateStatus`/`mergeable`, and the check runs on the head SHA (name, status, conclusion, run id). Do not drive it manually through the UI.
- **D-08:** Run **two variants**:
  - **(a) The Pitfall 8 window.** Close the PR, wait until the close run has completed and its skipped check runs exist on the head SHA, then reopen and merge immediately.
  - **(b) The UAT literal.** Close, reopen and merge with no wait.
- **D-09:** Make **3 attempts per variant**. **Stop at the first reproduction**, because one accepted merge proves the gap. A successful merge consumes the PR, so each attempt needs its own fresh PR and branch.
- **D-10:** The verdict is defined as follows.
  - **Race lost (gap proven):** `gh pr merge` succeeds while any of the five required contexts **from the reopen run** is queued, in progress, or missing on the head SHA.
  - **Blocked:** the merge is refused until the reopen run's five contexts complete.
  - Both outcomes are captured as evidence: the check-runs JSON plus the merge command's exit code and stderr. A red check is **not** required to call the race lost.

### Outcome handling
- **D-11 (stop condition):** **If any attempt shows the race lost, stop the phase and bring the evidence to the operator.** No fix is chosen in advance. This follows the 29.4 D-03 / 29.5 D-04 / D-07 precedent. A fix changes caller files that Mode B consumers own (27-RESEARCH Pitfall 13a). One candidate is a separate caller file for `closed` with a different job id, the Pitfall 8 "zero-risk alternative". Any fix needs a measured operator decision and probably a release.
- **D-12:** **If every attempt is blocked**, item 3 **passes on evidence**. A **new ADR (next free number, ADR-033)** records the measured behaviour and resolves ADR-024 "What was NOT verified" item 2. ADR-024 is not edited (ADRs are append-only, CLAUDE.md).

## Specific Ideas

- The existing evidence already shows the precondition: 27-08 saw `skipped` runs from the close run sitting newer than `success` on head `7c47270`. Variant (a) reproduces exactly that state before reopening.
- "Blocked" must be distinguished from "not mergeable for another reason", for example a merge conflict or an unenforced ruleset. D-04/D-05 prove enforcement first, and the merge stderr is captured verbatim, as the ADR-019 refusal string was.

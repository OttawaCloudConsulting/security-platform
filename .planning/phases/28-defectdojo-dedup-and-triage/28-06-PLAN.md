       time DefectDojo re-parents the default-branch copy but copies only active/verified/mitigated state, never the
       FP/OOS/RA flag, so a PR-engagement disposition is lost and the default-branch copy is left inactive and
       un-dispositioned (RESEARCH Caveat A). A disposition on the default-branch original also suppresses future PR
       duplicates of it (measured: P-SUPPRESS).
    5. `## Dispositions` (D-15): a table with columns State | How to set it | What reimport does. Rows: Under Review
       (D-23: the implicit untriaged queue; every new finding lands here; exits by setting Verified or a
       disposition; give the UI filter description and the API query from the interfaces block; say the native
       "Under Review" flag is the multi-reviewer request workflow and is not used); Verified/Active (verified is
       preserved by reimport); False Positive; Out of Scope; Risk Accepted; Mitigated (set automatically by
       close_old_findings when the scanner stops reporting it; reopens if it comes back, which is intended). The
       "what reimport does" column uses the measured tuples from 28-05: FP and OOS are additionally shown as
       Mitigated from the next scan while keeping their flag and staying inactive; RA is unchanged; none is ever
       reactivated; no reimport flag is needed, and do_not_reactivate must stay off so fixed issues reopen on
       regression. Also: a dispositioned finding the scanner no longer reports is mitigated; for RA that removes the
       acceptance.
    6. `## Risk acceptance` (D-22): use full risk acceptance only (a Risk Acceptance object); do not enable simple
       risk acceptance on the product. The bootstrap sets the form's default expiry to 90 days. Expiry date and
       reason (decision details) are MANDATORY by this procedure because DefectDojo does not enforce them. On expiry
       Celery beat (every 3 h) reactivates the finding and it returns to Under Review. Include the API POST shape.
    7. `## API examples`: fenced bash blocks for the Under Review query and the FP, OOS and RA calls, using
       `https://defectdojo.example.com` and a token read from a file with `-H @header-file` (never on argv).
    8. `## Expected noise`: legacy-hash scanners (Checkov, Gitleaks, Semgrep, SARIF/tflint) include the line number,
       so a PR that shifts lines shows an existing issue as new on the PR engagement (Pitfall 8); cross-tool SCA
       findings for the same vulnerability (Trivy, npm audit, pip-audit) do not collapse in 3.3.200 (D-07; quote
       one measured example pair from the 28-05 CROSSTOOL lines), so triage each tool's finding; if another PR is
       still open, a default-branch copy can stay a duplicate of that PR's finding until that PR closes (Caveat B).

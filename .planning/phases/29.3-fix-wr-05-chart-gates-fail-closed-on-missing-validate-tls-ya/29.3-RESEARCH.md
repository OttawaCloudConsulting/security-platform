### Locked Decisions

#### Gate fail-closed behaviour (both scripts)
- **D-01:** **Guard 1 (the chart directory is absent) becomes FAIL, exit 1.** A missing or renamed chart directory is a chart defect, not a vacuous pass. Both SKIP guards are removed.
- **D-02:** **Guard 2 (the guard template is absent) becomes an early FAIL, exit 1.** It stays at the top of the script, before preflight, and prints a `FAIL: <LABEL>: ...` line, then exits 1. This is the shape the 26-REVIEW WR-05 fix text shows. For DefectDojo the label is `TLS-GUARD-PRESENT`. The check counts do not change: 22 for DefectDojo and 18 for Nexus. The three count literals per script, and the DefectDojo README's `PASS - 22 checks` line, therefore stay true. The later render checks are not run when a guard fails.
- **D-03:** Guard 1 also uses an early `FAIL: <LABEL>:` line with exit 1. The label for Guard 1, and the Nexus Guard 2 label, are at Claude's discretion. They must be stable, because CI matches them (D-14).
- **D-04:** Rewrite the "INTERMEDIATE-COMMIT CONVENTION — VACUOUS-PASS" header block in both scripts to describe the fail-closed convention. Remove the "do not 'complete' this script by deleting these two" instruction. Update the exit-code comment so that it names the guard FAILs under exit 1.
- **D-05:** The exit-code contract is unchanged: 0 pass, 1 chart defect (now including a missing chart or guard), 2 preflight or infrastructure.

#### Recording the convention change
- **D-06:** **Add a new ADR-030** (append-only; no existing ADR changes): "standing chart gates fail closed and run in CI". It covers the removal of the vacuous-pass convention for both gates, the `chart-gates.yml` workflow, `CHART_GATE_MODE`, the report-only default and the bucket rules (D-11..D-14), and the WR-04 hint fold. Add the index row to `docs/adr/README.md`. No existing ADR records the SKIP convention (it lived only in script headers), so nothing is superseded. ADR-023 item 8 (the Nexus hint gap) is answered in ADR-030's prose.

#### CI home and trigger
- **D-07:** **Add a new dedicated workflow, `.github/workflows/chart-gates.yml`.** Do not add a job to `defectdojo-import-proof.yml` (15-30 min, DefectDojo only) or `pr-security.yml` (the thin caller for the `security / ...` contexts).
- **D-08:** **Triggers:** `pull_request` with a paths filter (`kubernetes/**`, `scripts/check-*-chart.sh`, `.github/workflows/chart-gates.yml`), `push` to `main` on the same paths, and `workflow_dispatch`. Use `pull_request`, never `pull_request_target`. No secrets. The workflow-level permissions are `contents: read`.
- **D-09:** **Two named jobs:** `chart-gate-defectdojo` and `chart-gate-nexus`. Do not use a matrix. Check-run names must be stable and readable. Each job builds only its own chart's dependencies. Do not use `security` as a job id (that is the frozen prefix of the required contexts).
- **D-10:** **Do not add the check to the branch ruleset.** Do not change `set-required-checks.sh`. Blocking is controlled by a repo variable instead (D-11). DI-04 recorded that `main` currently has no required contexts.

#### Blocking mode: repo variable (operator's "feature flag")
- **D-11:** **Add a new repo variable, `CHART_GATE_MODE`, with the values `blocking` and `report-only`.** When it is unset or empty, the mode is **`report-only` (the default, non-blocking)**. It is separate from `GATE_MODE`, which drives the five scan jobs in `security.yml`, so the operator can flip each one on its own.
- **D-12:** **Any other value fails the job (always red)** with a message that names the value, for example: `CHART_GATE_MODE=<x> is not blocking|report-only`. A typo made while trying to enable blocking must not silently leave blocking off.
- **D-13:** **Buckets:**
  - **Chart-defect bucket (follows the mode):** the gate exits 1. This includes the guard FAIL and the chart-directory FAIL. The chart-defect bucket also covers a gate that exits 0 but whose last line does not start with `PASS -` (vacuous pass, operator choice). In `report-only`, the job emits `::warning` plus a job-summary entry that carries the FAIL lines, and the job stays green. In `blocking`, the job is red.
  - **Always-red bucket (ignores the mode):** the gate exits 2 (preflight: missing binary or tarball, meaning the gate never ran), any other exit code, a failed helm repo add or dependency build, an invalid `CHART_GATE_MODE` (D-12), and any failed negative case (D-15).

#### What CI asserts
- **D-14:** **A PASS is exit 0 AND a last line that starts with `PASS -`.** The count is not checked, so the workflow does not duplicate the 22/18 literals.
- **D-15:** **Standing negative cases in every run of each job.** They run after the positive run, in a throwaway copy of the checkout. They must never mutate the tree that the positive run used.
  - (a) The guard template is removed. The gate must exit 1 and print the guard FAIL label.
  - (b) The chart directory is removed or renamed. The gate must exit 1 and print the chart FAIL label.
  - If either expectation is not met, the job is red regardless of `CHART_GATE_MODE`.
- **D-16:** The mode and bucket logic lives in the workflow step. The gate scripts stay mode-agnostic: they keep the plain 0/1/2 contract, and CI interprets it.

#### Preflight in CI, and the WR-04 fold
- **D-17:** **Fold in Phase 26 WR-04 for both gates.** The preflight hint must print a command that works on a fresh clone: `helm repo add <name> <repository derived from Chart.yaml>` followed by `helm dependency build <chart dir>`. The URL is derived with `yq` from `.dependencies[].repository` and is never hardcoded. This is about two lines per script.
- **D-18:** **CI builds dependencies the same way:** read `.dependencies[].repository` from each `Chart.yaml`, `helm repo add`, then `helm dependency build`. No repository URL is hardcoded in the workflow YAML. The CI step therefore proves the D-17 hint. The researcher confirms whether `kubernetes/nexus` needs `repo add` (ADR-023 item 7/8 says "probably").
- **D-19:** **Tools:** pin Helm **v4.3.0** with the existing download, sha256 verify and extract step from `defectdojo-import-proof.yml` (never `curl | sh`). The gate relies on Helm 4 behaviour, such as the `--namespace` note in `check-defectdojo-chart.sh`. The researcher checks whether `ubuntu-latest` ships `yq` v4 (mikefarah) and `jq`. If it does not, pin and verify them in the same way. Actions are pinned by SHA, as the other workflows are (`actions/checkout@3d3c42e5...  # v7.0.1`).

#### Release and proof
- **D-20:** **Merge to `security-platform` `main`. No tag and no `v1` move.** Consumers are not affected: `security.yml`, the callers and the chart templates do not change. The SUMMARY states this. The 29.4 release hand-off in STATE.md is unchanged.
- **D-21:** **Proof:**
  - (1) Before the fix, a local RED shows that both current gates exit 0 with SKIP when the guard or the chart directory is removed.
  - (2) A local offline proof covers the workflow's mode logic: unset, `report-only`, `blocking` and a typo value, against exit 0 with PASS, exit 0 without PASS, exit 1 and exit 2. This proves the step script, not a copy of it. Extract it from the committed YAML, as 29.2 P-EXTRACT did.
  - (3) A live PR run shows both jobs green and every negative case passing under the default (unset) mode.

## Summary

Both offline chart gates in `security-platform` (`scripts/check-defectdojo-chart.sh`, 564 lines; `scripts/check-nexus-chart.sh`, 403 lines; both unchanged on `origin/main` `72cb174539cca5e3a2841f7977a221a90c41326e`) open with two SKIP guards that exit 0. I reproduced D-21(1) RED locally on a `git archive origin/main` copy: removing `validate-tls.yaml`, removing `job-provision.yaml`, or renaming either chart directory makes the gate print `SKIP: ...` and exit 0 in all four cases. Both gates resolve their repo root from `dirname "$0"` and `cd` into it, so a throwaway `cp -a` copy works as long as the negative case runs **the copy's** script.

Both charts' dependencies are `https://` classic repositories, and **both** fail `helm dependency build` on a fresh Helm config with `Error: no repository definition for <url>. Please add the missing repos via 'helm repo add'`. Running `helm repo add <dep name> <url read by yq>` first makes both builds succeed, leaves `Chart.lock` byte-identical, and both gates then print `PASS - 18 checks, 0 failures` / `PASS - 22 checks, 0 failures`. This was measured with Helm v4.3.0. ADR-023 item 8 (the Nexus gap) is therefore a **verified** defect, not just a likely one. `kubernetes/nexus/README.md` L144 still has the build-only instruction. GitHub's `ubuntu-24.04` image (the current `ubuntu-latest`) ships mikefarah yq 4.53.6 and jq 1.7, so no download is needed for them. It ships Helm 3.22.0, so the existing pinned Helm v4.3.0 step is still required. `ubuntu-latest` moves to Ubuntu 26.04 between 2026-10-19 and 2026-11-19. That image ships yq 4.53.6, jq 1.8.1 and Helm 4.3.0, so the plan should assert tool versions rather than trust the label.

**Primary recommendation:** Make both guards early `FAIL: <LABEL>:` + `exit 1` (labels `CHART-DIR-PRESENT`, `TLS-GUARD-PRESENT`, `PROVISION-JOB-PRESENT`), and derive the preflight hint with `yq -r`. Add `chart-gates.yml` with two jobs whose step bodies are byte-identical and parameterised only by literal job-level `env:`. The steps are: Helm v4.3.0 pinned install, a yq/jq assert, a deps build from `Chart.yaml`, a `gate` step holding the mode/bucket logic (no `${{` in the body, mode passed via `env:`), and a `negative` step with `if: ${{ !cancelled() }}` that runs in `$RUNNER_TEMP` copies. Prove the `gate` body offline by extracting it with `yq` from the committed YAML and running a 16-case matrix (4 modes x 4 outcomes) against a stub gate.

### Pattern 1: Early guard FAIL (recommended labels)
```bash
# ── Guard 1. The chart directory must exist (fail closed, ADR-030) ───────────
if [ ! -d "$CHART_DIR" ]; then
  echo "FAIL: CHART-DIR-PRESENT: ${CHART_DIR} does not exist — the chart was deleted or renamed"
  exit 1
fi

# ── Guard 2. The TLS guard template must exist (fail closed, ADR-030) ────────
if [ ! -f "${CHART_DIR}/templates/validate-tls.yaml" ]; then
  echo "FAIL: TLS-GUARD-PRESENT: ${CHART_DIR}/templates/validate-tls.yaml is missing — the issuer guard is gone"
  exit 1
fi
```
Nexus Guard 2: `FAIL: PROVISION-JOB-PRESENT: ${CHART_DIR}/templates/job-provision.yaml is missing — the required rootPassword guard is gone`. Same `CHART-DIR-PRESENT` label in both scripts. Use the exact `FAIL: <LABEL>: ` prefix that `fail()` produces (L115 / L97), so CI can match `^FAIL: <LABEL>:` without special cases. Guard FAILs print no `FAILED - n check(s)` line. That is acceptable, because D-14/D-15 match on exit code and label only.

### Pattern 2: Derived fresh-clone hint (WR-04 fold, D-17)
```bash
# DefectDojo (inside the existing `if [ ! -f "$DEP_TGZ" ]` branch)
DEP_NAME=$(yq -r '.dependencies[0].name' "${CHART_DIR}/Chart.yaml")
DEP_REPO=$(yq -r '.dependencies[0].repository' "${CHART_DIR}/Chart.yaml")
echo "PREFLIGHT FAIL: subchart not vendored — ${DEP_TGZ} does not exist"

```

### Pattern 3: Workflow job skeleton (byte-identical bodies, P-EXTRACT friendly)

name: Chart Gates

on:
  workflow_dispatch: {}
  pull_request:
    paths:                          # repeated verbatim under push (no YAML anchors, Pitfall 8)
      - kubernetes/**
      - scripts/check-*-chart.sh
      - .github/workflows/chart-gates.yml
  push:
    branches: [main]

### Anti-Patterns to Avoid
- **`continue-on-error` driven by the mode:** it hides exit 2, which D-13 forbids.
- **Running the workspace script in a negative case:** `REPO_ROOT` comes from `dirname "$0"`, so `bash scripts/check-...sh` tests the unmutated tree. Always run `bash "$copy/scripts/check-${CHART}-chart.sh"`.
- **Mutating `$GITHUB_WORKSPACE` in negatives:** violates D-15. Copy first, and check `git status --porcelain` afterwards.
- **`${{ ... }}` inside a `run:` body:** breaks P-EXTRACT, because the extracted body would differ from what runs, and it is an injection vector. Pass values via `env:`.
- **A `shell:` key on the extracted steps:** changes semantics from `bash -e {0}` to `bash --noprofile --norc -eo pipefail {0}`. The offline proof must run the body exactly as the runner does (29.2 contract).
- **Hardcoded repo URLs in YAML:** violates D-18.
- **A matrix:** violates D-09.

| Problem | Don't Build | Use Instead | Why |
|---------|-------------|-------------|-----|
| Helm install in CI | `curl \| sh` get-helm script | Existing pinned tarball + `sha256sum -c` + version assert step | Already live-proven. Repo rule: never `curl \| sh` |
| Reading workflow step bodies for the proof | sed/awk over YAML | `yq -r '.jobs."<job>".steps[] \| select(.id == "gate") \| .run'` | Same tool as P-EXTRACT (29.2 used `yq -o=json` + python). ## Common Pitfalls

### Pitfall 1: Deps step turns a chart-dir deletion into always-red
**What goes wrong:** If a PR deletes `kubernetes/<chart>`, a `deps` step that runs `yq` on `Chart.yaml` fails first. That is always red, but D-13 puts the chart-dir FAIL in the mode-following bucket.
**How to avoid:** `deps` begins with `if [ ! -f "kubernetes/${CHART}/Chart.yaml" ]; then echo "::notice::kubernetes/${CHART}/Chart.yaml absent — skipping dependency build; the gate reports it"; exit 0; fi`. The gate then prints `FAIL: CHART-DIR-PRESENT:` (exit 1, bucketed). Residual case: if the chart dir is present but `Chart.yaml` is gone, the guards pass and preflight 4's `yq` fails, so the gate exits 2 and the job is always red. That is acceptable (the chart is broken in a way that is not a gate decision). Say so in ADR-030.

### Pitfall 2: Negative-case precondition makes guard/dir deletion always red
**What goes wrong:** If the PR itself already deleted the guard template or the chart dir, negative case (a) or (b) has nothing to remove in the copy. It cannot produce the expected label (for example, with the chart dir gone, case (a) gets `CHART-DIR-PRESENT`, not `TLS-GUARD-PRESENT`), so the job is red under D-15 regardless of mode. **Net effect:** deleting the security control or the chart is always red, even in report-only. The positive run's bucketed warning is overridden in practice.
**Recommendation:** keep it red (fail closed on deletion of the control the gate exists to protect). Make the negative step check its precondition explicitly and print a clear `::error::precondition: <path> absent in the checkout — the positive run already reports it; a deleted guard is always red (ADR-030)` instead of a confusing label mismatch. State this interaction in ADR-030 prose. **The operator should be told** (see Open Question 1).

### Pitfall 3: Running the wrong copy's script
**What goes wrong:** `bash scripts/check-x-chart.sh` from any CWD tests the tree that contains the script (L47-48 / L45-46).
**How to avoid:** `bash "${dir}/scripts/check-${CHART}-chart.sh"`. Verified locally: `(cd /; bash $COPY/scripts/check-nexus-chart.sh)` tested the copy.

### Pitfall 4: Capturing rc under `bash -e`
**What goes wrong:** with no `shell:` key the runner uses `bash -e {0}`, so a bare non-zero gate kills the step before the bucket logic runs.
**How to avoid:** `rc=0; bash "scripts/check-${CHART}-chart.sh" > "$out" 2>&1 || rc=$?`. Validate `CHART_GATE_MODE` **before** running the gate (D-12 applies even when the gate passes). Do not rely on `pipefail`: `grep` with no match inside `{ ...; } >> "$GITHUB_STEP_SUMMARY"` must be `|| true`-guarded, or written so a no-match does not end the step.

### Pitfall 5: `helm repo add` and non-https repositories
`helm repo add x oci://...` fails ("is not a valid chart repository ... invalid reference") [VERIFIED: local Helm v4.3.0]. Both charts use `https://` today. The `deps` step (and optionally the hint) should accept only `https://*`, and any other scheme should be always red with an explicit message. Both Chart.yaml files have exactly one dependency (`.dependencies | length == 1`). Iterate `.dependencies[]` in CI anyway. Re-adding an identical name+URL is a no-op ("already exists with the same configuration, skipping", rc 0). The same name with a different URL fails (rc 1). That is fine on a fresh runner, and worth a note for operators who already have a `defectdojo` repo pointing elsewhere.

### Pitfall 6: Workflow-command data in `::warning`
Gate FAIL lines can contain helm output and therefore PR-controlled text. Emit **one `::warning` per FAIL line** (no embedded newlines). The runner decodes `%25`/`%0D`/`%0A` in command data [ASSUMED: runner `toCommandValue` escaping]. Escape `%` as `%25` if exact text matters. Put the full text in `$GITHUB_STEP_SUMMARY` inside a fenced block. The step summary is appended with `>>`, and it is limited to 1 MiB per step [CITED: docs.github.com workflow-commands].

### Pitfall 7: Paths-filter side effects on other workflows
`defectdojo-import-proof.yml` triggers on `kubernetes/defectdojo/**` (L63). **Any edit to `kubernetes/defectdojo/README.md` in this PR starts the 15-30 min kind proof.** `kubernetes/nexus/**` is not in its paths. `scripts/check-*-chart.sh` and `chart-gates.yml` are not in its paths. `pr-security.yml` runs on every PR regardless (its five checks are not required on `main`, DI-04).

### Pitfall 8: actionlint / YAML details
Do not use YAML anchors in workflows: GitHub only recently began accepting them, and actionlint versions differ [ASSUMED]. Repeat the paths list. Quote nothing in `paths` that needs quoting (`kubernetes/**` is fine unquoted, matching L63 of import-proof). Run `actionlint` locally (1.7.12 present) before pushing.

### Pitfall 9: Runner image migration window
`ubuntu-latest` moves to Ubuntu 26.04 from 2026-10-19 to 2026-11-19 [CITED: actions/runner-images#14748]. The 26.04 image ships Helm 4.3.0, yq 4.53.6 and jq 1.8.1, so nothing breaks. The tool-assert step and the Helm version `case` make any drift loud.

### Pitfall 10: macOS bash 3.2 in local proofs
`/bin/bash` is 3.2 (`declare -A` fails, as measured). Every local command must call `bash` from PATH (5.3.20).

## Code Examples

### deps step body (D-18)
```bash
chart_dir="kubernetes/${CHART}"
if [ ! -f "${chart_dir}/Chart.yaml" ]; then
  echo "::notice::${chart_dir}/Chart.yaml is absent; skipping the dependency build so the gate reports the missing chart"
  exit 0
fi
n="$(yq -r '.dependencies | length' "${chart_dir}/Chart.yaml")"
i=0
while [ "$i" -lt "$n" ]; do
  name="$(yq -r ".dependencies[${i}].name" "${chart_dir}/Chart.yaml")"
  repo="$(yq -r ".dependencies[${i}].repository" "${chart_dir}/Chart.yaml")"
  case "$repo" in
    https://*) ;;
    *) echo "::error::${chart_dir}/Chart.yaml dependency ${name} has repository '${repo}'; only https:// repositories are supported"; exit 1 ;;
  esac
  helm repo add "$name" "$repo"
  i=$((i + 1))
done
helm dependency build "$chart_dir"
```
(Measured locally: repo add + build succeeded for both charts, and `Chart.lock` was unchanged for both [VERIFIED].)

### gate step body (D-11..D-14, D-16)
```bash
case "${CHART_GATE_MODE}" in
  '') mode=report-only ;;
  blocking|report-only) mode="${CHART_GATE_MODE}" ;;
  *) echo "::error::CHART_GATE_MODE=${CHART_GATE_MODE} is not blocking|report-only"; exit 1 ;;
esac
echo "chart gate mode: ${mode}"
out="${RUNNER_TEMP}/chart-gate-${CHART}.out"
rc=0
bash "scripts/check-${CHART}-chart.sh" > "$out" 2>&1 || rc=$?
cat "$out"
last="$(tail -n 1 "$out")"
case "$rc" in
  0)
    case "$last" in
      'PASS -'*) echo "chart-gate-${CHART}: PASS"; exit 0 ;;
    esac
    why="exit 0 without a terminal 'PASS -' line (vacuous pass)" ;;
  1) why="chart defect (exit 1)" ;;
  2) echo "::error::check-${CHART}-chart.sh preflight failed (exit 2): the gate never ran"; exit 1 ;;
  *) echo "::error::check-${CHART}-chart.sh exited ${rc} (expected 0, 1 or 2)"; exit 1 ;;
esac
{
  echo "### chart-gate-${CHART}: ${why} (mode: ${mode})"
  echo '```'
  grep '^FAIL' "$out" || tail -n 5 "$out"
  echo '```'
} >> "$GITHUB_STEP_SUMMARY"
if [ "$mode" = blocking ]; then
  echo "::error::chart-gate-${CHART}: ${why}; CHART_GATE_MODE=blocking"
  exit 1
fi
grep '^FAIL' "$out" | while IFS= read -r line; do
  echo "::warning title=chart-gate-${CHART}::${line//%/%25}"
done || true
echo "::warning title=chart-gate-${CHART}::${why}; report-only (set CHART_GATE_MODE=blocking to fail the job)"
exit 0
```
`${line//%/%25}` needs bash. The runner's default is bash, and the proof must use bash 5. Treat the details as discretion, but keep the bucket semantics exactly as in D-13.

### negative step body (D-15)
```bash
failed=0
for case_id in a b; do
  dir="${RUNNER_TEMP}/neg-${CHART}-${case_id}"
  rm -rf "$dir"
  cp -a "$GITHUB_WORKSPACE" "$dir"
  if [ "$case_id" = a ]; then
    target="${dir}/kubernetes/${CHART}/templates/${GUARD_TEMPLATE}"; label="$GUARD_LABEL"
    if [ ! -f "$target" ]; then echo "::error::negative (a): precondition failed, ${target#"$dir"/} is absent in the checkout"; failed=1; rm -rf "$dir"; continue; fi
    rm "$target"
  else
    target="${dir}/kubernetes/${CHART}"; label="$CHART_LABEL"
    if [ ! -d "$target" ]; then echo "::error::negative (b): precondition failed, kubernetes/${CHART} is absent in the checkout"; failed=1; rm -rf "$dir"; continue; fi
    mv "$target" "${target}.renamed-by-negative-case"
  fi
  rc=0
  out="$(bash "${dir}/scripts/check-${CHART}-chart.sh" 2>&1)" || rc=$?
  if [ "$rc" -eq 1 ] && printf '%s\n' "$out" | grep -q "^FAIL: ${label}: "; then
    echo "negative (${case_id}) PASS: exit 1 with FAIL: ${label}:"
  else
    echo "::error::negative (${case_id}): expected exit 1 and 'FAIL: ${label}:', got exit ${rc}"
    printf '%s\n' "$out"
    failed=1
  fi
  rm -rf "$dir"
done
if [ -n "$(git -C "$GITHUB_WORKSPACE" status --porcelain)" ]; then
  echo "::error::the workspace changed during the negative cases"; git -C "$GITHUB_WORKSPACE" status --porcelain; failed=1
fi
exit "$failed"
```

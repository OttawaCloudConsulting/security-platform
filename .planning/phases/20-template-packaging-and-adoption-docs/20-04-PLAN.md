<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| consumer repository visibility → code-scanning ingestion | Availability differs by visibility and account plan; the pipeline must not claim success it cannot have, nor fail for a capability it cannot get |
| caller `permissions:` → callee | The caller's job-level set is the CEILING; a callee can reduce but never elevate |
| shipped comment → consumer's mental model | A false comment in a copied file is an unverifiable claim propagating to 6+ repositories |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-20-05 | Repudiation | the six SARIF verify steps | mitigate | Capability condition compounded onto the existing `if:`; step count asserted still 6, no `continue-on-error` added, no upload step's `if:` touched |
| T-20-14 | Information disclosure | the five artifact verify steps | accept | Deliberately NOT guarded — artifact upload uses `ACTIONS_RUNTIME_TOKEN`, and 17-04 recorded its fork/Dependabot behaviour as an open observation; guarding it would suppress a check that may well pass |
| T-20-04 | Elevation of privilege | `gate_mode` resolution in the caller | mitigate | Banner states the `gh variable set` mechanism and reproduces the forbidden-passthrough trap; `grep` asserts zero placeholder tokens, so no edit-invited `""` can suppress the default |
| T-20-12 | Tampering | frozen identifiers in copied files | mitigate | `name: security` and the five job names diffed byte-for-byte against `origin/main` |
| T-20-15 | Spoofing | a consumer's Dependabot config | mitigate | Header states that a LOCAL `./` ref is never updated while an EXTERNAL `@v1` ref is (2023-03-13), so a Mode B consumer does not conclude its pin is frozen and stop watching it |
| T-20-SC | Tampering | package-manager installs | accept | None in this plan; every `uses:` SHA is untouched |
</threat_model>

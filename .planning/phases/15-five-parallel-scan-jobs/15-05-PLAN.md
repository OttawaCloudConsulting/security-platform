<notes>
**TARGET REPOSITORY.** All GitHub operations target `OttawaCloudConsulting/security-platform`, resolved
at runtime from `git -C repos/security-platform remote get-url origin`. Never `git push` from the outer
documentation repo — the two share a remote URL but have disjoint histories.

**This plan is not autonomous.** Task 1 is a blocking checkpoint. Do not merge, do not close the PR, and
do not touch `main` before the user's explicit approval. `workflow.auto_advance` does not apply — a
merge to a shared default branch is an irreversible action, which the project's session-management rule
requires be confirmed with the user first.

**If the user reports an issue instead of approving:** record what they observed verbatim in the
SUMMARY, leave the PR open, leave `main` untouched, and stop. A workflow fix belongs in a revision of
Plan 03 followed by a re-run of Plan 04 — not in an ad-hoc patch from this plan.

  ecosystem, so no version-update PR will target `fixtures/package-lock.json`. Dependabot *alerts* are a
  separate repo-level setting. Probe it after the merge; if alerts are noisy, the remedy is an `ignore`
  rule in a later phase, not a change now.

  gate mode WILL block on them and needs either `--baseline-path` or fingerprint-form `.gitleaksignore`

- A3 / Pitfall 7 (the `--severity HIGH,CRITICAL` filter applies to the report file, not just the exit
  code): Phase 17 must decide whether DefectDojo wants full-severity artifacts.

  vs Trivy v0.74.0 / Gitleaks 8.30.1 in CI): left deliberately divergent; convergence is a later-phase call.
- CONTEXT.md's D-02 and D-03 were implemented per their corrected forms (RESEARCH C-1/C-2/C-3), not their

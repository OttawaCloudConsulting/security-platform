jobs.defectdojo-import
  name: DefectDojo Import
  needs: [sast, iac, sca, container, secrets]
  if: always() && github.event.action != 'closed' && vars.DEFECTDOJO_URL != ''
  runs-on: ubuntu-latest ; timeout-minutes: 20
  permissions: contents: read, actions: read
  concurrency: group defectdojo-${{ github.repository }}-${{ github.head_ref || github.ref_name }},
               cancel-in-progress: false            (RESEARCH Pitfall 9)
  NO job-level env:, NO shell: key, NO defaults: block
  steps (in order):
    dd-gate      name "Gate — DefectDojo token present?"
                 env DD_TOKEN: ${{ secrets.DEFECTDOJO_API_TOKEN }}
                 body reads DD_TOKEN and runner GITHUB_ACTOR; writes enabled=true|false to $GITHUB_OUTPUT.
                 GITHUB_ACTOR == dependabot[bot] -> print
                   "SKIP: Dependabot run — DefectDojo import refused even if a Dependabot secret exists"
                 empty DD_TOKEN -> print
                   "SKIP: DEFECTDOJO_API_TOKEN is not available to this run (fork or Dependabot pull request, or the secret is unset) — nothing sent to DefectDojo"
                 never echoes the token value
    dd-download  uses actions/download-artifact@3e5f45b2cfb9172054b4087a40e8e0b5a5461e7c  # v8.0.1
                 if: steps.dd-gate.outputs.enabled == 'true'
                 with: pattern '*-results', merge-multiple: true, path: dd-reports
    dd-import    name "Import reports into DefectDojo (reimport-scan)"
                 if: steps.dd-gate.outputs.enabled == 'true' ; continue-on-error: true
                 env:
                   DD_URL:          ${{ vars.DEFECTDOJO_URL }}
                   DD_TOKEN:        ${{ secrets.DEFECTDOJO_API_TOKEN }}
                   DD_PRODUCT:      ${{ vars.DEFECTDOJO_PRODUCT || github.repository }}
                   DD_PRODUCT_TYPE: ${{ vars.DEFECTDOJO_PRODUCT_TYPE || 'CI' }}
                   DD_INSECURE:     ${{ vars.DEFECTDOJO_INSECURE }}
                   DD_CA_CERT:      ${{ vars.DEFECTDOJO_CA_CERT }}
                   DD_REPORTS_DIR:  dd-reports
                   DD_RESULTS_FILE: dd-import-results.json
                 body also reads runner-provided GITHUB_EVENT_NAME, GITHUB_HEAD_REF, GITHUB_REF_NAME,
                 GITHUB_SHA, GITHUB_RUN_ID, GITHUB_SERVER_URL, GITHUB_REPOSITORY (never ${{ }}).
    dd-verify    name "Verify DefectDojo import landed"
                 if: always() && steps.dd-gate.outputs.enabled == 'true' ; NO continue-on-error
                 env DD_IMPORT_OUTCOME: ${{ steps.dd-import.outcome }} ; DD_RESULTS_FILE: dd-import-results.json

Results file (written by dd-import, read by dd-verify and by the proof harness), JSON object:
  { "branch", "engagement_name", "product_name", "product_type_name",
    "tls_mode": "verified-system" | "verified-ca" | "insecure",
    "attempted": [ { "file", "scan_type", "test_title", "http_code", "test_id", "engagement_id",
                     "product_id", "statistics" } ],
    "skipped":   [ { "file", "reason" } ] }

Import table (glob in DD_REPORTS_DIR -> scan_type -> test_title), verified at DefectDojo 3.3.200:
  semgrep-results.json  -> "Semgrep JSON Report" -> semgrep
  checkov-results.json  -> "Checkov Scan"        -> checkov
  trivy-fs.json         -> "Trivy Scan"          -> trivy-fs
  trivy-image.json      -> "Trivy Scan"          -> trivy-image
  gitleaks-results.json -> "Gitleaks Scan"       -> gitleaks
  npm-audit-*.json      -> "NPM Audit v7+ Scan"  -> npm-audit-<N>   (N from the filename)
  pip-audit-*.json      -> "pip-audit Scan"      -> pip-audit-<N>
  tflint.sarif          -> "SARIF"               -> tflint

Per-file request (one curl per file, D-04):
  POST <DD_URL without trailing slash>/api/v2/reimport-scan/
  curl -sS -o <resp file> -w '%{http_code}' <tls args> -H @<header file> -F file=@<path>
       --form-string for: scan_type, product_type_name, product_name, engagement_name, test_title,
       auto_create_context=true, close_old_findings=true, branch_tag (first 150 chars of branch),
       commit_hash=GITHUB_SHA, build_id=GITHUB_RUN_ID,
       source_code_management_uri=GITHUB_SERVER_URL/GITHUB_REPOSITORY
  header file: created with os.open mode 0o600 (or umask 077) in a tempfile.mkdtemp() dir, content
  "Authorization: Token <DD_TOKEN>", removed in a finally block. The token never appears on argv or in logs.
  tls args: DD_INSECURE == "true" -> ["-k"] plus
              "::warning::DefectDojo TLS verification is OFF (DEFECTDOJO_INSECURE=true) — this run's findings were sent over an unverified connection"
            elif DD_CA_CERT non-empty -> write it to a 0600 temp file, ["--cacert", <file>]
            else -> []   (system trust store)
            If both are set, INSECURE wins, the warning fires, and a second line
              "::warning::DEFECTDOJO_CA_CERT is ignored because DEFECTDOJO_INSECURE=true"
            is printed.
  NO -q flag on curl (the proof harness supplies host resolution through CURL_HOME/.curlrc).

Branch resolution: GITHUB_HEAD_REF if GITHUB_EVENT_NAME == "pull_request" else GITHUB_REF_NAME;
empty -> print "FAILED: cannot resolve a branch name" and exit 1. engagement_name = "ci/" + branch.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| PR author → runner | Branch names (`github.head_ref`) are attacker-controlled strings that reach the import step |
| runner → DefectDojo | Findings and the API token cross the network to a consumer-supplied URL |
| caller repo → callee | Secrets and vars flow from the consumer repository into this public workflow |
| workflow → third-party action | download-artifact runs in the same job as the token-bearing step |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-27-01 | Tampering / Elevation | dd-import run: body | mitigate | Branch arrives only via runner env GITHUB_HEAD_REF / GITHUB_REF_NAME; zero `${{` in the body (gate NO-INTERPOLATION) |
| T-27-07 | Information disclosure | curl -F with branch/product values | mitigate | `--form-string` for every non-file field; only `file=@<path>` uses -F, and paths come from the fixed import table |
| T-27-02 | Information disclosure | API token | mitigate | Token in step env of dd-gate/dd-import only; written to a 0600 header file read via `-H @file`; removed in finally; never printed; no `set -x` |
| T-27-08 | Information disclosure | download-artifact action | mitigate | No job-level env; the download step has no token in its env |
| T-27-04 | Spoofing | TLS to DefectDojo | mitigate | Verified by default; `--cacert` for a private CA; `-k` only under DEFECTDOJO_INSECURE=true with a `::warning::` on every run (gate INSECURE-WARNING) |
| T-27-06 | Information disclosure | fork / Dependabot runs | mitigate | Secrets are absent on fork and Dependabot runs; dd-gate skips on an empty token and also refuses GITHUB_ACTOR dependabot[bot] |
| T-27-10 | Denial of service | merge gating | mitigate | Import job not in set-required-checks.sh (gate SIDE-CHANNEL-NOT-REQUIRED); dd-import continue-on-error; its red verify cannot block a merge |
| T-27-SC | Tampering | actions/download-artifact | mitigate | Full-SHA pin 3e5f45b2cfb9172054b4087a40e8e0b5a5461e7c (v8.0.1, first-party, RESEARCH audit) |
| T-27-11 | Elevation | scan jobs skipped on closed | accept | A closed-PR run reports skipped (= success) contexts; exploiting the reopen window needs close, reopen and merge before the reopen run queues (LOW); recorded in ADR-024 |
</threat_model>

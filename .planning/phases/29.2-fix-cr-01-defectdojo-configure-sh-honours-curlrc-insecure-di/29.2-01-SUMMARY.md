# Phase 29.2 Plan 01: P-CURLRC offline negative case (RED) Summary

An offline P-CURLRC case now reproduces the Phase 28 CR-01 leak. It uses a self-signed python3 TLS listener on 127.0.0.1 and a hostile `CURL_HOME` curlrc, and a no-`-q` control proves the curlrc is live. In the RED run, every in-scope DefectDojo client sent its token to the unverified listener: configure, lifecycle-assert, homelab-validate, and the committed dd-import and dd-delete bodies. All six target lines are FAIL, and each names the `REQUEST ... auth=yes` lines the listener received.

## What was built

**security-platform, branch `fix/phase-29.2-curlrc`, cut from origin/main `fdabac9`. One local commit, `b11f677`, not pushed.**

- `write_tls_listener_py`: this is the RESEARCH "Tested listener", copied verbatim and written from a heredoc. It is run only as `python3 <file>`.
- `curlrc_fixture_up`: builds the cert from a `-config` cnf (no `-ext` or `-addext`), starts the listener in the background, and polls for the port file in a bounded loop (at most 50 × 0.2s). It then writes the hostile curlrc: `insecure`, `verbose`, `trace-ascii` → `p-curlrc-trace.txt`, `libcurl` → `p-curlrc-libcurl.c`, `cacert`, `location`, `location-trusted` and `resolve`. The function also sets `CURLRC_FIXTURE_ERR` on failure.
- `curlrc_fixture_down` (idempotent kill+wait) and `curlrc_reset`.
- `curlrc_new_token` generates a fresh 0600 40-hex dummy per target. `curlrc_counts` and `assert_curlrc_refused` implement the common assertion set: exit 1, ≥1 HANDSHAKE-FAIL, 0 REQUEST, no success marker or `http=200`, token absent, no `Authorization` or `^[<>*] ` lines, a `TLS verification result` line, and no trace or libcurl file.
- `prove_curlrc_refusal` runs the fixture, then the control, then the six target lines: `configure`, `lifecycle` (0600 wrapper), `homelab-tls-probe` and `homelab-token-get` (0600 wrapper, `KUBECONFIG=<empty file under PROOF_DIR>`, nonexistent context, no RESOLVE hook), `dd-import` (which also requires exactly 1 CONNECT) and `dd-delete`. If the fixture or the control fails, every target is recorded as FAIL `not evaluated: control failed`. The listener is stopped on every return path.
- `proof_skip` prints a line and leaves `PROOF_N` and `PROOF_FAILED` unchanged.
- The case is wired into `mode_scheme_only` and `mode_hook`, directly after `prove_http_refusal`. `curl` and `openssl` were added to the `--scheme-only` require_bins, and `openssl` to `--hook`. The single `--scheme-only` EXIT trap now also kills `$LISTENER_PID`, which is read when the trap runs.
- All six textual `run_body` calls in `prove_http_refusal` (seven invocations, because of the loop) now pass `DEFECTDOJO_RESOLVE=` (RESEARCH Pitfall 2). No assertion changed.
- `defectdojo-import-proof.yml`: `on.pull_request.paths` now includes `scripts/defectdojo-lifecycle-assert.sh` and `scripts/defectdojo-homelab-validate.sh`, and the header prose is updated. The harness header's Modes and Assertion groups lines now cite P-CURLRC.

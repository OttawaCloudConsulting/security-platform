    Decision (numbered): 1 every DefectDojo API client (configure, lifecycle-assert, homelab-validate, security.yml
    dd-import and dd-delete) passes curl `-q` as argv[1]; 2 success requires curl exit 0 AND ssl_verify_result 0 AND

    (D-16, keeps the released v1 surface additive); the operator scripts have no insecure mode; 3 dd-import stops at
    the first transport failure; 4 DEFECTDOJO_RESOLVE is a harness-only hook (strict host:port:IPv4, host and port equal
    to the URL, exit 2 otherwise; only the IP changes, hostname verification stays), never set by the workflow and not
    a consumer setting (D-07); homelab-validate has none (no resolve need); 5 no raw curl stderr, verbose or trace
    output in any failure line; `%{errormsg}` and a truncated DefectDojo response body are allowed (D-08, D-18); 6 token
    files must be regular, readable, one line of 40 lowercase hex (WR-01/WR-02; configure, lifecycle-assert,
    homelab-validate); 7 the proof: P-CURLRC offline against a python ssl listener with a hostile curlrc, the guard
    cases, the hostile live curlrc with an end-of-run trace-absence assertion, and the CURLRC gate (check-workflow-uploads
    now 20 checks). State: "This record extends ADR-025 **in prose**: ADR-025's 'TLS is verified' now also means
    ambient curl configuration cannot switch verification off, and the gate count ADR-025 gives as 19 is now 20.

    Consequences: v1 does NOT carry the security.yml part until the Phase 29.4 release, which cuts one additive v1.x tag
    and moves v1 for 29.2 and 29.4 together; @main consumers have it now; self-hosted runners' legitimate curlrc
    entries (proxy, cacert) no longer apply to these calls (env vars still do; CA via DEFECTDOJO_CA_CERT); a hand-set
    non-40-hex admin key is refused with exit 2 and must be regenerated.
    What was NOT verified (numbered): env-scoped settings (CURL_CA_BUNDLE, SSL_CERT_FILE/SSL_CERT_DIR, SSLKEYLOGFILE)

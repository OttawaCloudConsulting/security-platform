# Phase 29.2 Plan 03: defectdojo-configure.sh curlrc / verify / token-file fix Summary

`defectdojo-configure.sh` now does four things:

- It calls every curl with `-q` first, so the operator's curlrc is never read.
- It fails closed unless curl exit is 0 and `ssl_verify_result` is 0.
- It discards curl stderr.
- It refuses a malformed `DEFECTDOJO_RESOLVE` hook or token file with exit 2 before any connection.

This closes Phase 28 CR-01, WR-01 and WR-02 for the superuser bootstrap.

## What was built

The work is in security-platform, on branch `fix/phase-29.2-curlrc`, commit `3baeba1`. That is 3 commits above origin/main. It is not pushed.

- **api():** the argv is `["curl", "-q", "-sS", "--proto", "=https", "--proto-redir", "=https", ...]` with `-w "%{http_code} %{ssl_verify_result} %{errormsg}"`. When the hook is set, one `--resolve` value is appended. curl runs with `stderr=subprocess.DEVNULL`. The transport branch comes first: it runs when `returncode != 0 or verify != "0"`, prints `FAILED: <METHOD> <path>: curl exit N, http C, TLS verification result V (must be 0): <errormsg>` and exits 1. An HTTP-code mismatch after a verified transfer prints only the DefectDojo body (`text[:500]`, or `(empty)`). Nothing reads `proc.stderr`.
- **DEFECTDOJO_RESOLVE:** the value is read at module level. main() validates it after the https refusal and before the token-file stat, at lines 210, 227 and 236. The check is a fullmatch against the RESEARCH Pattern 3 regex. The host must equal `urlsplit(url).hostname`, ignoring case, and the port must equal the URL port (default 443). Any failure prints `FATAL: DEFECTDOJO_RESOLVE must be host:port:IPv4 with the host and port of DEFECTDOJO_URL (a test hook; leave it unset)` and exits 2.
- **Token file:** the script first stats the file. If the stat fails, it prints the existing "does not exist" FATAL. The remaining checks run in this order:
  - `S_ISREG`, else `is not a regular file`
  - the existing `& 0o077` check
  - the wrapped `open()`, where an OSError prints `cannot be read: <strerror>`
  - at most one trailing `\r\n` or `\n` is stripped (never `.strip()`), then the content must fullmatch `[0-9a-f]{40}`, else `must hold one bare DefectDojo API token: 40 lowercase hex characters on one line, no 'Token ' prefix`

  Every refusal goes to stderr, exits 2 and names the path, never the content.
- **Header:** the old "Plain curl is called, so a curlrc under CURL_HOME is honoured" is replaced by a CURL CONFIG paragraph. It covers `-q` and the three curlrc paths, the exit-0 plus verify-0 rule, that stderr is never printed, and cites ADR-029 and Phase 28 CR-01. The invocation block now documents the test hook and the token format. The exit-code block lists the TLS-result exit 1 and the new exit-2 causes.
- **README:** one sentence was added after "TLS is always verified" in the bootstrap section. It says the script passes curl `-q`, so the operator's curlrc (`~/.curlrc`, `$CURL_HOME/.curlrc`) is ignored. `curlrc` appears once, and `DEFECTDOJO_RESOLVE` does not appear (0).

### Transport hardening (applies to every DefectDojo curl call in all three targets)
- **D-04:** Pass **`-q` as curl's first argument** on every DefectDojo API call, so that no curlrc is read. `-q` works only in first position; the plan and the tests must respect that.
- **D-05:** **Every call also fails closed on `%{ssl_verify_result}` not equal to `0`.** This is defence in depth. It covers GET, PATCH and the re-GET in configure, every lifecycle-assert request, and the CI import and cleanup requests. Add `%{ssl_verify_result}` to `-w`, and treat any value other than `0` (including a missing value) as a failure: exit 1, "TLS verification result X (must be 0)". This follows the harness's existing `write_dedup_py` `get()` pattern. The check runs after the request, so `-q` (D-04) is what actually keeps the token off an unverified peer. The check catches a regression of D-04.
- **D-06:** **Host-resolution hook: a single env var `DEFECTDOJO_RESOLVE`**, passed as one `--resolve <value>`. The same mechanism is used in all three targets.
  - The value must match a strict `host:port:address` pattern. Its host and port must equal those of `DEFECTDOJO_URL`, otherwise the script refuses with exit 2 (preflight).
  - When unset or empty, the hook does nothing.
  - The hook only chooses the IP. TLS verification against the URL's hostname still applies, so the hook cannot weaken TLS.
  - A curl config file option (`-K`) was rejected, because a config file could contain `insecure` again.
- **D-07:** **`DEFECTDOJO_RESOLVE` is harness-only in `security.yml`.** The workflow bodies read the env var, but the workflow never sets it. It is not a `workflow_call` input, a repository variable or a secret, and it is not documented in `docs/adoption-guide.md`. Only the proof harness sets it when it runs the extracted bodies. No new consumer surface is added to v1. A comment in the body must say that it is a test hook and unset in real use.
- **D-08:** **Never echo raw curl stderr** on failure in any of the three targets. The failure line prints only: method and path, the curl exit code, the HTTP code, `ssl_verify_result`, and a fixed error string (curl's `%{errormsg}`, or a mapped exit-code message). Header or trace text must never reach output. The researcher verifies that `%{errormsg}` exists on the curl versions in use (it needs curl >= 7.75: macOS system curl, ubuntu-latest, and the ARC runner image). If it is not available, map the exit codes. The review's "scrub `Authorization:` lines" option was rejected as a fragile denylist.

## Summary

All claims about curl behaviour below were measured in this session with the macOS system curl (`/usr/bin/curl` 8.7.1, MultiSSL, `LibreSSL/3.3.6`) against a python3 `ssl` listener with a self-signed cert. The measurements confirm the defect and the fix. Without `-q`, a `CURL_HOME/.curlrc` holding `insecure` + `verbose` makes curl complete the handshake with an unverified peer and send `Authorization: Token ...`. The listener logged `REQUEST ... auth=yes`, and `verbose` printed the header to stderr. With `-q` as the **first** argument, curl exits 60, the listener logs `CONNECT` then `HANDSHAKE-FAIL`, and no HTTP request arrives. With `-q` in **second** position, curl silently reads the curlrc and the token is sent. `-q` also blocks `$HOME/.curlrc` and `$XDG_CONFIG_HOME/curlrc` (measured).

**`-q` is the fix; the `ssl_verify_result` check (D-05) is only defence in depth, and it cannot catch every hostile curlrc.** Measured: a curlrc holding `cacert = <attacker's cert>` (no `insecure`) gives `ssl_verify_result 0`, exit 0, and the token is sent. The post-request check passes because verification "succeeded" against the attacker's trust root. A curlrc `insecure` line does produce `18` (self-signed) even though the request went through, so D-05 catches `insecure` specifically. Also, `ssl_verify_result` is `0` when no TLS happened at all (connection refused, exit 7). So the D-05 predicate must be `rc == 0 AND verify == "0" AND http == expect`, never `verify == "0"` alone.

**One locked decision conflicts with a released consumer surface. The planner must resolve it (Open Question 1).** `security.yml` still ships `DEFECTDOJO_INSECURE=true` → `-k` (L1443-1448, L1837-1842). ADR-025 keeps it in so many words ("`DEFECTDOJO_INSECURE=true` only with a warning"), and `docs/adoption-guide.md` documents it (L688, L777-785). Measured: `-k` against a self-signed peer gives `ssl_verify_result 18`. So an unconditional D-05 check in the two bodies would turn every `DEFECTDOJO_INSECURE=true` consumer red on the 29.4 release, and D-02 calls that release *additive*. Recommendation: apply `-q` unconditionally, and gate the `ssl_verify_result` check in the bodies on `tls_mode != "insecure"`. CONTEXT.md's "there is no option to switch it off" is true for `configure.sh` and `lifecycle-assert.sh`. It is not true for `security.yml`.

**Primary recommendation:** Build the harness negative case (P-CURLRC) first and prove it RED against the unfixed code (the 27-11 pattern). Then put `-q` first, add `-w '%{http_code} %{ssl_verify_result} %{errormsg}'`, add the `DEFECTDOJO_RESOLVE` → `--resolve` hook, and remove every stderr echo in all four call-site families. Then make the harness curlrc hostile, including `trace-ascii` and `libcurl` output files whose **absence** proves that no curl in the live run read the curlrc.

### Pattern 1: python call site (configure.sh `api()`, dd-import L1512, dd-delete `api()` L1782)
```python
# Source: 28-REVIEW CR-01 fix shape + measured -w behaviour (curl 8.7.1)
resolve = env.get("DEFECTDOJO_RESOLVE", "")   # test hook: set only by the proof harness; unset in real use
cmd = ["curl", "-q", "-sS", "--proto", "=https", "--proto-redir", "=https",
       "-X", method, "-o", resp_path,
       "-w", "%{http_code} %{ssl_verify_result} %{errormsg}"] + tls_args
if resolve:
    cmd += ["--resolve", resolve]
cmd += ["-H", "@" + hdr_path, url + path]
proc = subprocess.run(cmd, stdout=subprocess.PIPE, stderr=subprocess.DEVNULL,   # stderr never read (D-08)
                      universal_newlines=True)
code, verify, errmsg = ((proc.stdout or "").strip().split(" ", 2) + ["", "", ""])[:3]
code = code or "000"
if proc.returncode != 0 or verify != "0":          # rc first: verify is "0" on a refused connection
    print("FAILED: {} {}: curl exit {}, http {}, TLS verification result {} (must be 0): {}".format(
        method, path, proc.returncode, code, verify or "none", errmsg or "no error message"))
    raise Failed()
if code != expect:
    ...  # existing body=text[:500] path, WITHOUT the proc.stderr fallback
```
- `stderr=subprocess.DEVNULL` is the simplest way to make "never echo stderr" structural. `-sS` still makes curl write the error to stderr, which is discarded. `%{errormsg}` carries the same text to stdout. [VERIFIED: measured]
- `%{errormsg}` is written last because it can contain spaces. Use `split(" ", 2)`.
- In security.yml `dd-import`, a TLS failure should **stop the loop** (return 1 after recording). Continuing would retry the token against the same peer for every report. In `dd-delete`, `raise Failed()` already stops.

### Pattern 2: bash call site (lifecycle-assert `api_request()` L402-419)
```bash
# shellcheck disable=SC2191
local args=(-q -sS --proto =https --proto-redir =https -H @"$HDR" -X "$method" -o "$out"
            -w '%{http_code} %{ssl_verify_result} %{errormsg}')
if [[ -n "${DEFECTDOJO_RESOLVE:-}" ]]; then args+=(--resolve "$DEFECTDOJO_RESOLVE"); fi
...
wout="$(curl "${args[@]}" "${BASE}${path}" 2> /dev/null)" || rc=$?
code="${wout%% *}"; rest="${wout#* }"; verify="${rest%% *}"; emsg="${rest#* }"
if [[ "$rc" -ne 0 || "$verify" != "0" ]]; then
  API_ERROR="${method} ${path}: curl exit ${rc}, http ${code:-none}, TLS verification result ${verify:-none} (must be 0): ${emsg}"
  return 1
fi
if [[ "$code" != "$expect" ]]; then
  API_ERROR="${method} ${path}: http ${code:-none} (expected ${expect}): $(snippet "$out")"   # body only, never $err
  return 1
fi
```
`-q` must be `args[0]`, because `curl "${args[@]}"` makes it argv[1]. The `2> "$err"` file and its `snippet "$out" "$err"` use (L405, L412, L415) are removed. **L885** (the dangling-duplicate enrichment curl) must get `-q`, `--resolve` and the verify check too. It currently has `-w '%{http_code}'`, `2>/dev/null` and `|| echo none`. Recommend: route it through a variant of `api_request` that returns the code for a 404-tolerant read. A verify failure there must `abort` rather than record `none`.

### Pattern 3: `DEFECTDOJO_RESOLVE` validation (preflight, exit 2)
Recommended regex (IPv4 only; the hook is harness-only, and the harness uses 127.0.0.1):
```
^([A-Za-z0-9](?:[A-Za-z0-9.-]{0,251}[A-Za-z0-9])?):([0-9]{1,5}):((?:[0-9]{1,3}\.){3}[0-9]{1,3})$
```
Then `host.lower() == urlsplit(url).hostname` and `int(port) == (urlsplit(url).port or 443)`. Measured with a python fullmatch: it accepts `defectdojo.smoke.test:18443:127.0.0.1` and a case-different URL host. It rejects `*:443:…` (wildcard, 7.64+), `+host:…` (the timeout prefix, 7.75+), `host:443:a,b` (multiple addresses) and a host that does not match the URL. `-host:port` (the curl removal syntax) is rejected by the leading `[A-Za-z0-9]`.
- bash (lifecycle): derive the host and port from `BASE` with `[[ "$BASE" =~ ^https://([^/:?#]+)(:([0-9]+))?(/.*)?$ ]]`. Lowercase with `tr '[:upper:]' '[:lower:]'`, not `${x,,}`, to stay bash-3.2-safe like the rest of the file.
- Order: configure.sh `https` refusal (exit 1, L173) → RESOLVE validation (Preflight, exit 2) → token file. lifecycle-assert: the URL checks at L246-254 → RESOLVE → token file at L257. The bodies: scheme refusal → RESOLVE validation (`sys.exit(2)` / return 2, as D-06 locks; `dd-verify` L1588 and `dd-cleanup-verify` L1931 only test `outcome != "success"`, so the code costs nothing downstream) → TLS label → header write. Keep the refusal ahead of `write_private(hdr_path` so that the SCHEME gate's ordering check still holds.
- `--resolve` does **not** bypass hostname verification. Measured: `--cacert cert2.pem --resolve other.example.com:P:127.0.0.1 https://other.example.com:P/` → exit 60, `SSL: no alternative certificate subject name matches target host name 'other.example.com'`, `ssl_verify_result 1`. The same cert with the matching host → `0`. [VERIFIED: measured, curl 8.7.1]

### Pattern 4: token-file validation (WR-01/WR-02)
DefectDojo 3.3.200 authenticates with `dojo.user.authentication.ExpiringTokenAuthentication(TokenAuthentication)` over `rest_framework.authtoken.models.Token` [CITED: raw.githubusercontent.com/DefectDojo/django-DefectDojo/3.3.200/dojo/user/authentication.py, settings.dist.py L798-799, L900]. It pins `djangorestframework==3.18.0` [CITED: 3.3.200 requirements.txt]. DRF 3.18.0 defines `key = CharField(max_length=40, primary_key=True)` and `generate_key()` returns `secrets.token_hex(20)` [CITED: encode/django-rest-framework 3.18.0 rest_framework/authtoken/models.py]. **So every token that DefectDojo mints (api-token-auth, the UI key page, `reset_token_for_user`) is exactly 40 lowercase hex characters.**

**Pick: `^[0-9a-f]{40}$`** (applied after stripping at most one trailing `\n`/`\r\n`):
- configure.sh: `os.stat` → `stat.S_ISREG` → mode `& 0o077` → `open()` wrapped in `try/except OSError` → Preflight. Read the content, then `token = raw[:-2] if raw.endswith("\r\n") else raw[:-1] if raw.endswith("\n") else raw`, then `re.fullmatch(r"[0-9a-f]{40}", token)`. A `Token ` prefix, an embedded newline or whitespace all fail, with exit 2 and a FATAL line that names the path and the expected format (never the content).
- lifecycle-assert: L284 `tr -d '\r\n'` **joins** a multi-line file into one string, so `abc\ndef` becomes `abcdef` and is accepted. Replace it with a check that the file has at most one line (for example `[[ "$(wc -l < "$CRED_FILE")" -le 1 ]]` plus a strip of one trailing CR). Tighten the regex from `^[A-Za-z0-9._-]+$` to `^[0-9a-f]{40}$`. Its `-f`/`-r` check (L259) already covers a directory and mode 000 as non-root.
- Risk if wrong: a token set by hand in the Django admin (a custom key) would be refused with a clear exit-2 message. An operator can regenerate it. This is LOW risk. The looser `[A-Za-z0-9]{20,128}` also blocks header injection, so the choice only affects how strict the check is.

### Pattern 5: harness pieces
- **Listener** (inline heredoc written by a `write_tls_listener_py PATH` function, the same shape as `write_read_py`; not a new committed script). The full tested source is under Code Examples ("Tested listener"). Its essentials: `ssl.SSLContext(PROTOCOL_TLS_SERVER)`, an `HTTPServer` subclass whose `get_request()` logs `CONNECT`, wraps the accepted socket with `server_side=True`, logs `HANDSHAKE-FAIL` and re-raises on `ssl.SSLError/OSError` (socketserver ignores an `OSError` from `get_request`), and a handler that logs `REQUEST <method> <path> auth=yes|no` and answers 500. It binds `127.0.0.1:0` and writes its port atomically (tmp + `os.replace`). Measured on python 3.9.6 (LibreSSL) and 3.12.0.
- **Cert** (no `-ext`/`-addext`): a small cnf with `[req] distinguished_name=dn, x509_extensions=v3, prompt=no`, `[dn] CN=defectdojo.curlrc.test`, `[v3] subjectAltName=DNS:defectdojo.curlrc.test, basicConstraints=critical,CA:TRUE`; then `openssl req -x509 -newkey rsa:2048 -nodes -days 1 -keyout key.pem -out cert.pem -config san.cnf`. Measured on LibreSSL 3.3.6. The SAN and `CA:TRUE` are needed so that the hostile `cacert = <cert>` line yields `verify 0` (a plain `-subj` CN-only cert gave `18` even when trusted). That makes a `-q` regression detectable **only** by the listener count, which is exactly the D-11 intent.
- **Hostile curlrc** (D-09, offline and live). All of these options exist on 7.81+ and 8.x:
  ```
  insecure
  verbose
  trace-ascii = "<PROOF_DIR>/curlrc-trace.txt"
  libcurl = "<PROOF_DIR>/curlrc-libcurl.c"
  cacert = "<listener cert>"        # offline only; live: any throwaway PEM
  location
  location-trusted
  ```
  Measured without `-q`: `trace-ascii` and `libcurl` each wrote the token to their file (1 match each). With `-q`, neither file is created. **The absence of both files at the end of `--hook` is a global proof that no curl in the live run (bodies, configure, harness helpers) read the curlrc.** **P-CURLRC's own curlrc must name DIFFERENT files** (e.g. `p-curlrc-trace.txt`, `p-curlrc-libcurl.c`): its no-`-q` control run creates and then deletes its files, and if it shared the global names it would erase the evidence of an earlier live-run regression, so the global absence check would pass vacuously. Recommend a final `P-TLS` (or `P-CURLRC`) assertion on that. `location-trusted` makes curl resend custom `Authorization` headers across hosts on a redirect (a header leak path). `cacert` swaps the trust root (the case D-05 cannot catch). `proxy-insecure`, `doh-insecure`, `ssl-no-revoke` (Schannel only) and `trace-config` (8.3+) are not worth adding: they need a proxy or DoH, are Windows-only, or are missing on older curl. Do not put `resolve` in the hostile curlrc: it would collide with `--resolve`.
- **Dummy token**: `p27http$(gen_secret 24)` (31 chars) fails `^[0-9a-f]{40}$`. The new transport cases need a 40-hex dummy, for example `od -An -tx1 -N20 /dev/urandom | tr -d ' \n'`. The existing P-HTTP/no-env/loose-perms cases keep passing either way, because they exit before content validation. Check each existing configure case's expectations against the new check order.
- **lifecycle-assert invocation**: `run_body` runs `bash -e "$body"` with **no argv**. Write a 0600 wrapper body into `PROOF_DIR` (`exec bash "<REPO_ROOT>/scripts/defectdojo-lifecycle-assert.sh" snapshot --product p --out "<dir>" --engagement ci/main --label curlrc`) and run it through `run_body`. The first API call (`resolve_product` → `api_get_all`) fails, which leads to `abort PREREQ-PRODUCT` → exit 1. Success markers to forbid: `: PASS -`, `ALL PASS`, `^snapshot `.
- **Per-target success markers to forbid**: configure `^(NO CHANGE|CHANGED:|VERIFIED:)`; dd-import `^IMPORTED:`, `http=201`; dd-delete `^DELETED:`, `^NOTHING TO DELETE`; all of them `http=200`.

### Pattern 6: static gate (optional 20th check)
Following the SCHEME precedent (`check-workflow-uploads.sh` L630-667): assert that `'"curl", "-q"'` occurs in both `dd-import` and `dd-delete` runs, and that no `["curl", "-sS"` without `-q` remains. Bump `CHECK_COUNT = 20` and update every `PASS - 19 checks` literal in plan verify commands and docs (`grep -rn "19 checks"` first). This is cheap, but it is a grep. D-11 is explicit that the runtime listener proof is what counts.

### Anti-Patterns to Avoid
- **`-q` anywhere but argv[1]**: measured, curl silently reads the curlrc and sends the token.
- **`verify == "0"` as the whole check**: it is `0` on a refused connection (exit 7) and with a curlrc `cacert` attacker root.
- **Scrubbing `Authorization:` from stderr**: rejected in D-08. Discard stderr instead.
- **Adding `DEFECTDOJO_RESOLVE` to a step `env:`**: `extract_bodies` CONTRACT (L208-219) compares step env names exactly and would fail. That is the right D-07 guard, so leave CONTRACT unchanged.
- **A negative case that only shows "zero requests"**: this is also true if the listener is dead or the port is wrong. It needs the control request plus `CONNECT`/`HANDSHAKE-FAIL` evidence.

## Don't Hand-Roll

| Problem | Don't Build | Use Instead | Why |
|---------|-------------|-------------|-----|
| Ignoring curlrc | Unsetting/overriding `HOME`, `CURL_HOME`, `XDG_CONFIG_HOME` | `-q` as argv[1] | One flag covers every search location (measured for CURL_HOME, HOME, XDG) |
| Error text without secrets | stderr parsing or scrubbing | `-w '%{errormsg}'` + `stderr=DEVNULL` / `2>/dev/null` | Available on every curl in use (≥7.75) |
| Cert generation | python ASN.1 / `cryptography` | `openssl req -x509 -config san.cnf` | stdlib cannot mint certs; `-config` works on LibreSSL and OpenSSL |
| TLS test server | a raw socket loop | `http.server.HTTPServer` + `ssl.SSLContext` | Handshake failures surface as `OSError` in `get_request`, which is easy to count |
| Host pinning | an `/etc/hosts` edit or curlrc `resolve` | `--resolve` from `DEFECTDOJO_RESOLVE` | Hostname verification is kept (measured) |

## Common Pitfalls

### Pitfall 1: D-05 breaks `DEFECTDOJO_INSECURE=true` consumers
**What goes wrong:** an unconditional verify check in the dd-import/dd-delete bodies fails every run where the consumer opted into `-k` (verify is `18` for self-signed; measured).
**How to avoid:** gate the check on `tls_mode != "insecure"` (OQ1), and state it in ADR-029. P-INSECURE (L2863-2897) passes either way, because it makes no request.

### Pitfall 2: The global hook leaks into offline-style cases under `--hook`
**What goes wrong:** `mode_hook` will `export DEFECTDOJO_RESOLVE=<smoke host>:<port>:127.0.0.1` and a hostile `CURL_HOME`. `run_body` inherits the whole environment. P-CONFIGURE-GUARD cases with `DEFECTDOJO_URL=https://127.0.0.1:9` would then fail the RESOLVE host check (exit 2 with the wrong FATAL line) before the token-file guard they assert.
**How to avoid:** every `prove_http_refusal` `run_body` passes `DEFECTDOJO_RESOLVE=` (empty) explicitly, and P-CURLRC passes its own `CURL_HOME=` and `DEFECTDOJO_RESOLVE=`.

### Pitfall 3: `--scheme-only` lacks binaries
`mode_scheme_only` `require_bins jq yq python3` (L2066) has no `curl` and no `openssl`. Add both.

### Pitfall 4: WR-01 mode-000 case passes as root
Root can read a mode-000 file, so configure would proceed. ubuntu-latest runs as `runner` (non-root), and the operator Mac is non-root. Guard the case with `[ "$(id -u)" -ne 0 ]`, and record a SKIP rather than a false PASS when running as root.

### Pitfall 5: Stale assertion count
D-13 says "the 88-assertion import proof". The live proof has ended `PROOF PASS - 127 assertions` since Phase 28 (28-05, 28-07, 28-08, 28-09 SUMMARYs). `--scheme-only` is currently `PROOF PASS - 7 assertions` (measured today). Plans must assert `PROOF PASS - ` plus the new count, derived as 7 + N new cases, never 88.

### Pitfall 6: Token appears via `verbose` in harness helper stderr
`write_read_py`/`write_dedup_py`/L2309 print `(body or proc.stderr)[:300]` on failure, and `mint_token` and P-TLS echo `.err` files. With the hostile curlrc, any helper that missed `-q` would put the admin header into the harness log. `-q` on every helper is mandatory (D-09). The trace-file-absence assertion catches a missed one.

### Pitfall 7: `%{errormsg}` parsing
It contains spaces and is empty on success. Put it last in `-w` and split with maxsplit.

### Pitfall 8: Harness P-TLS inversion
The global live curlrc and the P-CURLRC curlrc must use distinct trace/libcurl file names (see Pattern 5). The current guard (L2134) aborts if the curlrc contains `insecure`. After D-09 it must **require** `insecure` and `verbose` (and the trace/libcurl lines), and P-TLS's own `api_call` must use `-q --resolve "$DEFECTDOJO_RESOLVE"`. Its detail text "host resolved by the CURL_HOME curlrc" (L2144) changes.

### Tested listener (measured on python 3.9.6/LibreSSL and 3.12.0; write it from a heredoc, e.g. `write_tls_listener_py PATH`)
```python
import http.server
import os
import ssl
import sys

cert, key, portfile, logfile = sys.argv[1:5]
ctx = ssl.SSLContext(ssl.PROTOCOL_TLS_SERVER)
ctx.load_cert_chain(cert, key)


def log(line):
    with open(logfile, "a", encoding="utf-8") as handle:
        handle.write(line + "\n")


class Handler(http.server.BaseHTTPRequestHandler):
    def _any(self):
        log("REQUEST {} {} auth={}".format(self.command, self.path,
                                          "yes" if self.headers.get("Authorization") else "no"))
        length = int(self.headers.get("Content-Length") or 0)
        if length:
            self.rfile.read(length)
        body = b'{"results": []}'
        self.send_response(500)
        self.send_header("Content-Type", "application/json")
        self.send_header("Content-Length", str(len(body)))
        self.end_headers()
        self.wfile.write(body)

    do_GET = do_POST = do_PATCH = do_DELETE = do_PUT = _any

    def log_message(self, *args):
        pass


class Server(http.server.HTTPServer):
    def get_request(self):
        sock, addr = self.socket.accept()
        log("CONNECT")
        try:
            return ctx.wrap_socket(sock, server_side=True), addr
        except (ssl.SSLError, OSError) as exc:
            log("HANDSHAKE-FAIL {}".format(type(exc).__name__))
            sock.close()
            raise          # socketserver swallows OSError from get_request and keeps serving


httpd = Server(("127.0.0.1", 0), Handler)
with open(portfile + ".tmp", "w", encoding="utf-8") as handle:
    handle.write(str(httpd.server_address[1]))
os.replace(portfile + ".tmp", portfile)
httpd.serve_forever()
```
Start it in the background (`python3 "$py" cert key portfile log & LISTENER_PID=$!`), poll for the port file (bounded loop), and kill it in the case's cleanup and in the EXIT trap. Note that the handler is single-threaded: a client that connects and sends nothing stalls it. Every client here is curl, so this does not arise.

## Security Domain

### Applicable ASVS Categories
| ASVS Category | Applies | Standard Control |
|---------------|---------|-----------------|
| V2 Authentication | yes (API tokens) | token only via `-H @0600file`; format validated (40-hex) |
| V5 Input Validation | yes | token regex; `DEFECTDOJO_RESOLVE` regex + host/port equality |
| V6 Cryptography | no hand-rolled crypto | curl/OpenSSL verification; never `-k` outside the documented INSECURE path |
| V7 Error Handling/Logging | yes | `%{errormsg}` only; stderr discarded |
| V9 Communications | yes | `--proto =https`, `-q`, the verify check, hostname verification kept under `--resolve` |

### Known Threat Patterns
| Pattern | STRIDE | Mitigation |
|---------|--------|------------|
| curlrc `insecure` / `cacert` → token to a MITM | Information disclosure | `-q` argv[1] (only effective control; measured) |
| curlrc `verbose`/`trace-ascii`/`libcurl` → token in logs/files | Information disclosure | `-q`; stderr discarded |
| curlrc `location-trusted` → token resent on a cross-host redirect | Information disclosure | `-q`; no `-L` in any call site |
| Multi-line token file → header injection | Tampering | 40-hex fullmatch |
| Hostile `DEFECTDOJO_RESOLVE` (e.g. a self-hosted runner `.env`) | Spoofing | Only the IP can change; hostname verified (measured J); host/port must equal the URL |
| Env `CURL_CA_BUNDLE`/`SSLKEYLOGFILE` | Info disclosure | Out of scope (environment control = code control); state it in ADR-029 |

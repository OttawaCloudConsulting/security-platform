# Phase 29.2 Plan 06: Hostile live curlrc, DEFECTDOJO_RESOLVE and inverted P-TLS Summary

**In `--hook`, the proof harness now writes a hostile global curlrc. Every harness curl helper passes `-q` and `--resolve DEFECTDOJO_RESOLVE`, and a final P-TLS assertion checks that the curlrc's trace and libcurl files were never created. The P-CURLRC listener race (DI-01) is fixed with a HANDSHAKE-OK terminal line and a settle poll.**

## Accomplishments

- **Task 1 (D-09):** `api_call` builds its command as `curl -q -sS --cacert "$DD_CA_FILE"`, followed by a `--resolve "$DEFECTDOJO_RESOLVE"` array when the variable is set. The empty array expands safely under bash 3.2 with `set -u`. The three python readers (`write_read_py`, `write_dedup_py`, and the inline reader that raises `ApiError`) now start with `["curl", "-q", "-sS", ...]` and append `["--resolve", value]` when `DEFECTDOJO_RESOLVE` is set. Four comments that still said resolution came from the CURL_HOME `resolve` entry were rewritten.
- **Task 2 (D-09):**
  - The P-TLS block generates a throwaway PEM with `gen_throwaway_cert`, the recipe factored out of `curlrc_fixture_up` (no `-ext`/`-addext`).
  - It writes the seven hostile directives with no `resolve` line, then exports `CURL_HOME` and `DEFECTDOJO_RESOLVE="${SMOKE_HOST}:${PF_PORT}:127.0.0.1"`.
  - It aborts unless the six required directives are present (anchored matches) and no `resolve` line exists.
  - The GET uses `api_call`. The PASS detail now reads "host resolved by DEFECTDOJO_RESOLVE; the hostile CURL_HOME curlrc was ignored".
  - A final P-TLS assertion runs after `prove_dedup_triage` and before the last `proof_finish`. It passes only if neither `curlrc-global-*` file exists. On failure it reports only the file size (`wc -c`), never the content.
  - The header's TLS paragraph was rewritten.
- **DI-01 (orchestrator directive, Rule 1):** The listener logs `HANDSHAKE-OK` after `wrap_socket` succeeds. `curlrc_counts` polls up to 3 s (30 × 0.1 s) for `CONNECT == HANDSHAKE-FAIL + HANDSHAKE-OK`. On the deadline it counts whatever is logged and appends `not settled after 3s` to the detail, and the existing assertions judge the result. Nothing passes by default. All four places that judge results call `curlrc_counts`: `assert_curlrc_refused`, `assert_guard_refused`, the homelab-token-get block and the dd-import pre-check.

## DI-01 investigation

- **Theory being tested:** the listener logs HANDSHAKE-FAIL after the body exits.
- **Instrumented runs (diagnostic not committed):** 30 sequential runs plus 48 runs under 6-way parallel load. None showed an unsettled dd-import or dd-delete count, so the race was not seen naturally.
- **Deterministic anomaly:** the diagnostic fired in every run for `proof-curlrc-homelab.log`, at `C=6 H=4 R=0`, unchanged after 0.5 s. The cause is `openssl s_client` (defectdojo-homelab-validate.sh:483). It does not verify, so the handshake completes and it closes without sending a request. Because of this, the directive's predicate `CONNECT == HANDSHAKE-FAIL + REQUEST` could never hold for homelab and would have used the full deadline on every run. The HANDSHAKE-OK line restores a predicate that always settles.
- **Mechanism confirmed by injection:** I added a temporary `time.sleep(0.3)` before the listener logs HANDSHAKE-FAIL.
  - Without the fix, the run reproduced the exact DI-01 line: `P-CURLRC FAIL configure: no HANDSHAKE-FAIL at the listener; [listener CONNECT=1 HANDSHAKE-FAIL=0 REQUEST=0]`. The late line also leaked into the next case after `curlrc_reset` (configure-token-dir showed `HANDSHAKE-FAIL=1` with `CONNECT=0`).
  - With the fix, the same delay gave `PROOF PASS - 30 assertions`. The sleep was then removed.
  - This shows the mechanism produces the observed symptom. It does not prove it caused the 29.2-05 flakes. No other explanation fits: a verifying curl sends an alert, and the server's `wrap_socket` raises on it.
- deferred-items.md DI-01 is marked RESOLVED.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] DI-01 P-CURLRC listener race (orchestrator directive)**
- **Found during:** plan 05; fixed before Task 1 so this plan's `--scheme-only` verify could not flake.
- **Issue:** `curlrc_counts` read the listener log right after `run_body`, but HANDSHAKE-FAIL can be logged after the body exits.
- **Fix:** the listener logs `HANDSHAKE-OK` after a completed handshake, and `curlrc_counts` waits up to 3 s for `CONNECT == HANDSHAKE-FAIL + HANDSHAKE-OK`. This differs from the directive's literal predicate, for the homelab `s_client` reason above. The intent is the same: nothing is passed silently, and on the deadline the result is judged on what is logged.
- **Files modified:** repos/security-platform/scripts/defectdojo-import-proof.sh
- **Commit:** 35363b7 (inside the single plan commit, as directed)

The check was meant for the P-TLS block.

### Auto-fixed / operator-approved

**1. [Wrong plan assumption] `security / DefectDojo Import` is not skipped on security-platform**
- **Found during:** Task 2, attempt 1/2 checks
- **Issue:** Must-have #3 expected the Import and Cleanup jobs to be skipped because "security-platform sets no DEFECTDOJO_URL". In fact the repo imports into the homelab DefectDojo: run 36738325155 imported 8 reports with http=201.
- **Resolution:** Operator decision "Accept, amend check (Recommended)". #3 now reads: Import passed with `TLS mode: verified-system` and "DefectDojo import verified". Cleanup is still skipped on the open PR.

**2. [Rule 1 - Bug, operator-approved] P-INSECURE harness regression introduced in plan 06**
- **Found during:** Task 2, attempt 2 (`PROOF FAIL - 1 of 151`)
- **Issue:** Plan 06 made `--hook` export `DEFECTDOJO_RESOLVE=<SMOKE_HOST>:<PF_PORT>:127.0.0.1` for the whole run (`scripts/defectdojo-import-proof.sh:2963`). P-INSECURE sets `DD_URL=https://127.0.0.1:9` and did not clear the variable. The dd-import body's test-hook guard therefore refused correctly with `FAILED: DEFECTDOJO_RESOLVE must be host:port:IPv4 ...` and exit 2, before it printed the TLS label. The product behaved correctly and the harness case was wrong. `--scheme-only` never runs P-INSECURE, so no offline gate caught it (DI-02).
- **Fix:** One added argument, `"DEFECTDOJO_RESOLVE="`, on the P-INSECURE `run_body` call. This is the same form as the P-CURLRC guard cases (lines 1270, 1449). The body treats an empty value as unset (`if resolve and not resolve_matches_url()`).
- **Files modified:** `repos/security-platform/scripts/defectdojo-import-proof.sh` (+2/−1)
- **Commit:** 415618c, a 7th commit. Plan 07 was written for six commits. The commit-count pins in plans 05 (5) and 06 (6) are now historical: this is a recorded deviation, not a violation.
- **Live confirmation:** attempt 4 shows `PROOF: P-INSECURE PASS DD_INSECURE=true -> ::warning:: line printed, exit 0, insecure attempted=0 skipped=8: no request was made`.

**3. [Known flake] Two KIND-CELERY-PING failures (attempts 1 and 3)**

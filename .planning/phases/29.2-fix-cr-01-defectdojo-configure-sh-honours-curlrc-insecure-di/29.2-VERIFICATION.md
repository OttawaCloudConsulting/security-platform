# Phase 29.2: Fix CR-01: defectdojo-configure.sh honours ~/.curlrc (insecure disables TLS) — plus WR-01/WR-02 Verification Report

**Phase Goal:** Ambient curl configuration (`~/.curlrc`, `$CURL_HOME/.curlrc`) can no longer cause a DefectDojo API
token to be sent to a peer whose TLS certificate was not verified (Phase 28 CR-01, plus WR-01/WR-02). Covers every
DefectDojo API client in `security-platform` (configure, lifecycle-assert, homelab-validate, the security.yml
dd-import/dd-delete bodies), proven by an offline hostile-curlrc negative case and a live proof run; merged to
`main` untagged (release batched with 29.4).

## Headline Finding

**The phase's core security goal IS achieved and independently reproduced.** `-q` is curl's first argument at
every DefectDojo API call site in all four clients (configure, lifecycle-assert, homelab-validate, the two
security.yml bodies), so ambient curlrc is never read, and a defence-in-depth `ssl_verify_result == 0` check
backs it up. This was re-run by this verifier (not taken from SUMMARY claims): `bash
scripts/defectdojo-import-proof.sh --scheme-only` → `PROOF PASS - 30 assertions` (own process, repo root
`repos/security-platform`, HEAD `47319b2` == `origin/main`), and the phase's own live GitHub Actions evidence
(`evidence/29.2-07-proof-run.log`) shows `PROOF PASS - 151 assertions` with all seven P-CURLRC target lines PASS
on `ubuntu-24.04`, matching the stated phase claim.

**One gap was found and it is not a security regression: a contract-consistency defect.** ADR-029 decision 6 and
both bash scripts' own header comments assert that the token file, "after at most one trailing line ending is
stripped," must fullmatch 40 lowercase hex. This verifier reproduced directly (not merely cited from
`29.2-REVIEW.md` WR-01) that `defectdojo-lifecycle-assert.sh` and `defectdojo-homelab-validate.sh` actually strip
*all* trailing newlines via bash command substitution before the regex check, so a token file with several
trailing blank lines is silently accepted by those two scripts while `defectdojo-configure.sh`'s Python
implementation (verified correct: strips exactly one `\r\n`/`\n`) correctly rejects it. No P-TOKEN-GUARD offline
case exercises this variant, so the harness does not catch it. This makes the accepted ADR's decision 6 and the
plan-04 must-have ("after stripping at most one trailing newline must fullmatch [0-9a-f]{40}") **false for 2 of
3 operator scripts**, even though it does not create a token-leak or header-injection path.

cited. `defectdojo-lifecycle-assert.sh` and `defectdojo-homelab-validate.sh` accept token files with multiple

fully and independently achieved (own `--scheme-only` PROOF PASS run, own `check-workflow-uploads.sh` PASS run,

contract-consistency defect between the code and an already-Accepted, append-only ADR, and it is invisible to the
existing P-TOKEN-GUARD offline coverage. Since ADRs are append-only per CLAUDE.md, resolution must fix the two
bash scripts (and add a covering P-TOKEN-GUARD case) rather than edit ADR-029.

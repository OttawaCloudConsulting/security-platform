<objective>
Close the single 29.2 verification gap (REVIEW WR-01): the two bash operator scripts strip every trailing newline via
`$(< file)`, accept a bare trailing CR, and silently drop NUL bytes, so they accept token files that
defectdojo-configure.sh's Python rejects. ADR-029 decision 6 (append-only, already correct) says "after at most one
trailing line ending is stripped". Fix the code to match the ADR, RED first.

Purpose: restore one token-file contract across all three clients, and make the harness catch future drift in both
directions (over-acceptance and over-rejection).
Output: two commits on a new branch `fix/phase-29.2-token-newline` in repos/security-platform (RED harness, GREEN
fix); one evidence file in this docs repository. Nothing pushed (push is plan 11).

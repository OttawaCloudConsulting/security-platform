# Phase 29.2 Plan 04: lifecycle-assert and homelab-validate curlrc / verify / token-file fix Summary

`defectdojo-lifecycle-assert.sh` and `defectdojo-homelab-validate.sh` now ignore the operator's curlrc (`-q` as argv[1]). They fail closed unless curl exit is 0 and `ssl_verify_result` is 0, and they never print curl stderr. They also refuse malformed token files, and lifecycle-assert refuses a malformed `DEFECTDOJO_RESOLVE` hook, with exit 2 before any connection. This carries the Phase 28 CR-01 fix to the last two operator-run DefectDojo clients.

## What was built

The work is in security-platform, on branch `fix/phase-29.2-curlrc`, commit `31d49d6`. The branch is 4 commits above origin/main and is not pushed.

**lifecycle-assert.sh**

- `api_transport METHOD PATH OUT [BODY]` is now the only curl call in the file:
  - `local args=(-q -sS --proto =https --proto-redir =https -H @"$HDR" -X "$method" -o "$out" -w '%{http_code}|%{ssl_verify_result}|%{errormsg}')`
  - `--resolve "$RESOLVE"` is added when the hook is set
  - stderr goes to `/dev/null`
  - it sets `HTTP_CODE`
  - if `rc != 0` or `verify != 0`, it returns 1 with `API_ERROR="<M> <path>: curl exit N, http C, TLS verification result V (must be 0): <errormsg>"`
- `api_request` wraps `api_transport` and adds the HTTP-code check. On a mismatch it quotes only the response body (D-18). The `err` local, the `req-N.err` file and `REQ_N` are gone.
- Enrichment loop: the old raw `curl ... || echo none` now calls `api_transport GET /api/v2/findings/<id>/ /dev/null || abort "D11-STEP5-READ" "$API_ERROR"`. Any HTTP code (200, 404, ...) is still recorded.
- Preflight, directly after `BASE=`: when `DEFECTDOJO_RESOLVE` is set, it must match the Pattern 3 regex. Its host must equal the `BASE` host after lowercasing with `tr`, and its port must equal the URL port (default 443) compared as base-10 integers. Otherwise the script prints `ERROR: DEFECTDOJO_RESOLVE must be host:port:IPv4 with the host and port of DEFECTDOJO_URL (a test hook; leave it unset)` and exits 2. The value is never echoed.
- Token: `cred="$(< "$CRED_FILE")"`, one trailing CR stripped, then `^[0-9a-f]{40}$`. Otherwise `unset cred` and `ERROR: DEFECTDOJO_ADMIN_TOKEN_FILE must hold one bare DefectDojo API token: 40 lowercase hex characters on one line, no 'Token ' prefix`, exit 2. The `-f`/`-r`/`-s`/mode checks, `set -C` and `unset cred` are kept.
- Header: the INTERFACE block and usage text give the token format and mark DEFECTDOJO_RESOLVE as a test hook. TOKEN HANDLING describes the format check. A new CURL CONFIG paragraph (ADR-029, Phase 28 CR-01) covers `-q`, the exit-0 plus verify-0 rule, no stderr, the single call site and the hook. The exit-2 list names the new causes.

**homelab-validate.sh**

- All six curl sites (check_tls, get_login_form, login POST, dashboard GET, foreign-Origin POST, measure_count) start `curl -q -sS --proto =https`. Each uses `-w '%{http_code}|%{ssl_verify_result}|%{errormsg}'`; the login POST uses `...|%{redirect_url}|%{errormsg}`. Each parses with `IFS='|' read -r`, sends stderr to `/dev/null`, and fails with `curl exit N, http C, TLS verification result V (must be 0): <errormsg>` prefixed by the method and URL or path. The six `.err` files and their `tr '\n' ' '` echoes are gone. The only remaining `tr '\n' ' ' < "$OUT/..."` sources are the SAN file and the celery output.
- check_tls: the `${tls_out##* }` parse is gone. The transport branch (`rc != 0 || verify != 0`) comes first, then the `http != 200` branch, then the SAN checks, which are unchanged. The `openssl s_client | openssl x509 -noout -ext subjectAltName` pipeline is byte-unchanged; it appears only as context in `git diff`.
- measure_count: a transport failure calls `fail "HOMELAB-API-TLS" "GET <path>: curl exit ..."`, sets `API_TLS_FAILED=1` and records a measurement gap. measure_state then does not attempt the findings GET and records a gap that says why. An HTTP-code mismatch keeps its MEAS_ERRORS entry.
- `--token-file` at argument validation must pass `-f` and `-r` (usage_error). At the read, `$(< file)`, one CR strip, `^[0-9a-f]{40}$`, else `unset token_val` and `usage_error "--token-file '<path>' must hold one bare DefectDojo API token: 40 lowercase hex characters on one line, no 'Token ' prefix"` (exit 2). Both checks run before check_tls opens the first connection.
- Header: a CURL CONFIG paragraph (ADR-029, Phase 28 CR-01) covers `-q` on all six calls, the exit-0 plus verify-0 rule, HOMELAB-API-TLS, no stderr, the token-file format, and that there is deliberately no host-resolution hook. `DEFECTDOJO_RESOLVE` appears once, in that sentence.

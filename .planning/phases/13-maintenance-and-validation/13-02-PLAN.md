<objective>
Build the GitHub API layer that `update` depends on: an authenticated request wrapper, a
whitespace-tolerant hardening of the existing resolver, and a new "latest release within a pinned
major version" resolver for the D-04 attempt-2 fallback path.

Purpose: three verified defects block everything downstream. The existing resolver's grep pattern
requires a space after the JSON colon, which hadolint's compact response does not have — so it
silently returns empty and `versions.conf` regenerates with stale hardcoded defaults. Unauthenticated
calls are capped at 60/hr, which this research session exhausted in minutes. And any new bare
assignment from a GitHub-touching function kills the script under `set -euo pipefail` when grep
matches nothing.

Output: `gh_api_get()`, `resolve_latest_in_major()`, a hardened `resolve_latest_version()`, and
fixture-driven unit tests that never touch the network.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| GitHub REST API → `setup.sh` | Untrusted remote JSON crosses here; `tag_name` values flow toward download URLs and `pipx install` specs |
| environment / `gh` keyring → `gh_api_get` | A read-only credential enters the process here |
| `gh_api_get` → curl argv / process list | A credential could leak into a process listing or shell history here |

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-13-01 | Tampering | `resolve_latest_in_major` output flowing into download URLs / install specs | mitigate | Strict `^${major}\.[0-9]+\.[0-9]+$` filter applied before the value is echoed; asserted as a named acceptance criterion. ASVS V5 |
| T-13-03 | Information Disclosure | `gh_api_get` token handling | mitigate | Token sent as an `Authorization: Bearer` header only, never interpolated into the URL; never passed to `log`/`info`/`warn`/`err`; no `set -x` in this path.

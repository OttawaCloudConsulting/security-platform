<objective>
Fix REVIEW.md WR-01 / VERIFICATION.md gap: in `repos/security-platform/workstation/setup.sh`,
`install_all_tools()` (lines 837-858) and `update_all_tools()` (lines 868-906) both do
`export PATH="$INSTALL_DIR:$PATH"` *before* the `case ":$PATH:" in *":$INSTALL_DIR:"*)` membership
check that decides whether to print the "add this to your PATH" warning. Because the export runs
first, the check always sees `$INSTALL_DIR` already present and the warning branch is dead code —
a user whose shell profile genuinely lacks `~/.local/bin` gets no warning from `install`, `setup`,
or `update`.

Fix: snapshot `$PATH` into a local variable BEFORE the export in both functions, and test that
snapshot (not the post-export `$PATH`) in the membership check. This is the only change in scope.

Purpose: Restore the PATH-missing warning's ability to actually fire, closing the one failed
plan-level truth from 13-VERIFICATION.md ("A user whose PATH lacks the install dir is told exactly
what line to add") without touching `doctor` (which already implements this correctly by never
exporting PATH — confirmed at setup.sh:1248, 1385-1386 — and is out of scope here).

Explicitly OUT OF SCOPE (raised in 13-REVIEW.md but NOT flagged as a verification gap — do not
touch):
- WR-02 (`run_installer` trusts installer exit code instead of re-probing the version, unlike
  `attempt_install`)
- WR-03 (Trivy/Syft/Grype installed via unpinned `curl | sh` from `main` with no checksum)

Do not refactor the PATH-check logic into a shared helper function. Two call sites, gap-closure
scope — inline the fix identically in both functions.

Output: `setup.sh` with the fix in both functions; a new `tests/test_path_warning.sh` proving the
warning fires/doesn't-fire correctly for both `install_all_tools` and `update_all_tools`; full test
suite green (143 existing + new assertions, all passing).

Test harness isolation contract (tests/run-tests.sh header comment, all four rules apply to the new
file):
- Rule 1: never call an assert helper inside a subshell — subshells emit via echo, the parent shell
  asserts against the captured string.
- Rule 2: capture pattern is `out=$( ( source "$SETUP_SH"; set +e; <stubs>; <call>; echo "rc=$?"; echo "$SOME_VALUE" ) 2>&1 )`.
- Rule 3: `set +e` immediately after sourcing inside the subshell (sourcing setup.sh imports
  `set -euo pipefail`).
- Rule 4: `set -e` safety (if tested) runs as its own `/bin/bash -c` process, not inline.

`update_all_tools` references `$PRECOMMIT_VERSION`, `$TRIVY_VERSION`, etc. via the `records` array
under inherited `set -u` — any subshell that sources setup.sh and calls `update_all_tools` directly
must either let setup.sh's own top-level version-var assignments stand, or stub `update_one_tool`
itself so the `records` loop body never dereferences an unset var problematically. Simplest safe
approach: stub `update_one_tool() { return 0; }` (it is called once per record; a no-op stub avoids
touching the network/installers entirely and sidesteps unbound-variable risk inside the loop body
itself, since the array entries are built from vars setup.sh already defines at top-level scope).
For `install_all_tools`, stub `run_installer() { :; }` for the same reason.

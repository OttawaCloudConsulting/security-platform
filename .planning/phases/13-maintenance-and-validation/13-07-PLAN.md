<objective>
Phase gate: prove on a real machine that `update` actually changes an installed tool's version, and
that `doctor` reports a real environment correctly.

Purpose: every automated test in this phase stubs the installer boundary, which is correct — it keeps
the suite offline, deterministic, and non-destructive. But that means no automated test ever proves
the single most important claim of MAINT-02: that `pipx install --force` really replaces an
already-installed pre-commit. The research verified that the *unforced* form exits 0 while doing
nothing; `--force` is documented and present in pipx 1.10.1, but forcing an actual **downgrade** was
never empirically executed because doing so mutates the developer's environment. This checkpoint
closes that gap, and closes it in both directions.

Output: a human-confirmed round trip, with `versions.conf` restored.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| test fixture edit → committed manifest | `versions.conf` is temporarily mutated and must not be committed |
| `setup.sh update` → developer's real pipx installation | This exercise deliberately changes installed software on the operator's machine |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-13-17 | Tampering | accidental commit of the temporarily-edited `versions.conf` | mitigate | Explicit `git checkout -- versions.conf` restore step, followed by a `git status --porcelain` confirmation step, both inside the human verification script; task 1 records the original value first |
| T-13-04 | Tampering | downgrade path exercised deliberately | accept | The downgrade here is operator-initiated against a version the operator selected from PyPI, not one resolved from an untrusted upstream response. The automated downgrade *guard* (fallback below pin) is covered by plan 04's tests |
| T-13-02 | Tampering | reinstalled pre-commit artifact | mitigate | Installation goes through the existing `_install_precommit` → pipx path against a pinned PyPI spec; no new install mechanism is introduced by this plan |
| T-13-06 | Information Disclosure | `update-failures.log` created during the optional step 11 | mitigate | Step 11 instructs deleting the log afterwards; plan 06 added the ignore rule, so it cannot be committed accidentally in this checkout; a criterion asserts no log remains |
| T-13-SC | Tampering | npm/pip/cargo installs | accept | The only package installed is `pre-commit`, already vetted in Phase 10, at a version the operator chooses from `versions.conf`. No new package enters the dependency set |
</threat_model>

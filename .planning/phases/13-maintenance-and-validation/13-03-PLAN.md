<objective>
Fix the two installer defects that make `update` structurally impossible, then build the two
primitives the update loop is composed from: an attempt-then-verify wrapper and a failure logger.

Purpose: `pipx install "pre-commit==X"` on an already-installed pre-commit prints "already seems to
be installed", changes nothing, and **exits 0** — verified on pipx 1.10.1. That means the existing
`install` command cannot upgrade pre-commit today, and `update` could never work. Separately,
`ensure_pipx` calls `exit 1` on bootstrap failure from inside `_install_precommit`, which would kill
the whole update run and directly violate the "continue updating the remaining tools" decision.

Output: `pipx install --force`, `ensure_pipx` returning instead of exiting, `attempt_install()`,
`log_update_failure()`, the new counters/constants, and offline unit tests for all of it.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| installer subprocess → orchestrator | Installer exit status is untrusted; only an independent version probe is believed |
| `setup.sh` → user's repo working tree | The failure log is written into a directory the user version-controls |
| downloaded release artifact → local filesystem | Binaries land in `$INSTALL_DIR` via the existing `_install_*` functions |

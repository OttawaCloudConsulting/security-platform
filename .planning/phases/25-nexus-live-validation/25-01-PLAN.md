`ANONYMOUS-PULL-DOCKER` — implement as a shell **function**, because the five legs are ordered and each
consumes the previous leg's output. `DOCKER_BLOB_MIN_BYTES=1000000`. Legs and their non-obvious

  1. `GET ${NEXUS_HOST}/v2/` must return **401** carrying a `WWW-Authenticate: Bearer` header. A 200 here
     is a FAILURE, not a success: no challenge was issued, so legs 2–5 measure nothing.
  2. Parse `realm` and `service` out of that challenge; both must be non-empty. A header-less GET returns
     200 even with the `DockerToken` realm removed (ADR-021 decision 5).
  3. `GET <realm>?service=<service>&scope=repository:${DOCKER_IMAGE_PATH}:pull` with **no credential** must
     return 200 and a non-empty `.token`.
  4. Manifest GET **with** `Authorization: Bearer <token>` and the OCI `Accept` headers must return 200 and
     JSON carrying `manifests` or `layers`. A 401 here with legs 1–3 green isolates the `DockerToken` realm.
  5. Resolve the `linux/amd64` child manifest, then fetch its first layer blob; assert 200 and a size

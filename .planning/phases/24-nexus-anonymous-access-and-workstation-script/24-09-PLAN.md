    `## Context` — the starting state: anonymous read closed on a default Nexus install; two
    standing gates written in Phase 23 specifically to make that claim measurable; ADR-020 stating
    the posture stays closed; and the eight-artefact inventory 24-RESEARCH.md found asserting it.

    `## Decision` — one bolded decision sentence per item, each followed by the mechanism and why
    the alternative was rejected:
    1. **Anonymous access is a wrapper-owned top-level `anonymous.enabled`, shipped `false`.** Not
       `nexus3.config.anonymous.*`, measured inert in Phase 23 (byte-identical render, removed in
       commit `a9c4f38`). The default is opt-in because a public chart must not open
       unauthenticated read for someone who installs it without reading `values.yaml`, and there is
       no TLS in front of the instance until Phase 25.
    2. **The anonymous PUT is unconditional, not guarded like the EULA POST.** The EULA guard exists
       because accepting a licence is a legal act performed on the consumer's behalf; anonymous
       access is declarative configuration persisted in the PVC, so a guarded skip would leave
       `anonymous.enabled: false` unable to CLOSE access a previous install or a human opened.
       Measured: the PUT returns 200 (not 204) and is idempotent.
    3. **The `DockerToken` realm is appended unconditionally, decoupled from `anonymous.enabled`.**
       This diverges from 24-RESEARCH.md's coupling and rests on the research's own measurement:
       a bearer token issued to the ADMIN user is also rejected 401 on the manifest request when
       the realm is inactive, so the realm governs Docker bearer validation generally rather than
       anonymity. Gating it would have made the docker-proxy repository unusable by every Docker
       client whenever anonymous is off — the shipped default — which would be a NEXUS-01 defect
       rather than an anonymity posture.
    4. **The realms PUT is a guarded GET-then-append-if-absent with a no-change skip.** Both traps
       measured: the PUT replaces the entire list, so omitting `NexusAuthenticatingRealm` locks out
       every user including admin; and the API stores duplicates, so a blind append in a Job that
       reruns on every upgrade grows the list without bound. The live gate asserts `DockerToken`
       exactly once and `NexusAuthenticatingRealm` still present after two consecutive passes.
    5. **The Docker pull path carries no `/repository/` segment.** This **closes ADR-020's
       `## What was NOT verified` item 2** — by reference, without editing ADR-020. Cite the
       measurement: `/v2/docker-proxy/...` returns 200, `/v2/repository/docker-proxy/...` returns
       404, and the third shape `/repository/docker-proxy/v2/...` returns 200 but no Docker client
       can be made to emit it, so it must never be documented as a pull target. Cite the full
       anonymous handshake the live gate now performs.
    6. **Per-repository routing means four different things.** npm has a native project scope; pip
       and Helm have none and route only through `PIP_CONFIG_FILE` and `HELM_REPOSITORY_CONFIG`,
       which is why one sourceable `.nexus-env` exists; Docker has no per-repository mechanism at
       all. State the `PIP_CONFIG_FILE` user-scope replacement as a measured consequence, not a
       caveat.
    7. **The Docker behaviour the operator selected**, with the A3 `VERDICT:` line quoted and the
       measurement method named (Docker-in-Docker, never the operator's daemon; the verdict rested
       on the Nexus components-endpoint delta because `registry-mirrors` falls back to Docker Hub
       silently). If a `daemon.json` branch shipped, record the ADR-009 obligation it carries and
       the tension with REQUIREMENTS.md's Out-of-Scope row, which the user amended knowingly.
    8. **Generated config is gitignored by default with a `--commit-config` escape hatch**, because
       a committed `.npmrc` pointing at one operator's Nexus is a dependency-resolution failure for
       every contributor who cannot reach it and an internal-hostname disclosure in a public repo.
    9. **The readiness knobs are wired through**, closing Phase 23 deferred item 2.
    10. **Checkov's zero coverage of `kubernetes/nexus` is accepted and documented**, closing Phase
        23 deferred item 3: both alternatives (a scanner-only values file, a committed rendered
        manifest) create a second artefact that drifts from the real one by construction, and this
        phase adds no Kubernetes resource — it adds environment variables to an existing Job.
        Restate the latent finding count so zero is not read as clean, and restate ADR-020's
        prohibition on weakening the credential guard to obtain coverage.

    `## Consequences` — `**Improved:**` then a `**Tradeoff — <named>.**` paragraph per real
    tradeoff, each saying what is mitigated and what is not. At minimum: anonymous read is
    all-repository and cannot be narrowed in place (`nx-anonymous` is `readOnly: true` with
    `nx-repository-view-*-*-read/browse`), so a future hosted repository is world-readable from
    creation — and that intersects ADR-010's dependency-confusion guidance, where a group repository
    must order hosted before proxy; the anonymous repository-inventory disclosure via
    `GET /v1/repositories`; plaintext HTTP until Phase 25's ingress, with NetworkPolicy explicitly
    out of scope; and the Community Edition usage ceilings becoming easier to reach once auth
    friction is gone.

    `## What was NOT verified` — numbered and bolded, and it must include at least:
    1. **No pull was performed by the operator's own Docker daemon.** Name the substitute used and
       why (Docker Desktop's VM network boundary; `crane` and a dind engine are the closest
       proxies).
    2. **`forceBasicAuth`'s documented-versus-measured divergence** carried forward from Phase 23.
    3. **Checkov still provides zero coverage of this chart** — accepted here, not solved.
    4. **Nothing was measured against a TLS-terminated Nexus**, and no ingress exists yet.
    5. **A custom anonymous role scoped to the four proxies was not built** — the remedy for the
       wildcard scope is described, not implemented.
    6. **Phase 25 input:** the private ArgoCD overlay must set `anonymous.enabled: true` explicitly
       or the first live deploy ships NEXUS-02 closed and the live gate goes red against real
       infrastructure. State this as a named hand-off so the overlay is written once.

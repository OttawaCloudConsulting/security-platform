<objective>
Settle Assumption A3 by measurement: can a path-routed Nexus Docker proxy
(`HOST/docker-proxy/...`, `pathEnabled: true`) actually be used as a Docker daemon
`registry-mirrors` target? CONTEXT.md's Docker decision rests entirely on this, and it has never
been tested.

Purpose: CONTEXT.md locks "the script writes `~/.docker/daemon.json`" AND flags the mechanism as
unmeasured, with an explicit instruction to prove or disprove it before committing further
Docker-routing work. If A3 holds — mirrors only mirror Docker Hub and require the mirror at the
registry root — then writing that key would configure a route that routes nothing: the exact
silent-corruption failure mode this project's rules exist to prevent.

Output: a reproducible probe, a recorded verdict with raw evidence, and an operator decision that
plan 24-07 implements without re-litigating.
</objective>

    Two independent readings, both zero-disruption. **Do not write or restart the operator's
    Docker daemon at any point in this plan.**

    **(a) Documentary.** Establish what the installed engine (Docker 28.3.2) does with a
    `registry-mirrors` entry that carries a path, and whether mirrors apply to registries other
    than Docker Hub. Use Context7 (`resolve-library-id` then `query-docs`) for the Docker engine
    daemon configuration and registry-mirror documentation; if Context7 has no usable entry, fetch

    explicitly, whether it is version-matched to 28.3.2 or not. This is a documentary reading, not
    a verdict — label it as such.

    **(b) Empirical validation, in a throwaway engine.** Create
    `24-evidence/a3-dind-probe.sh` (non-executable; invoked as `bash …`). Its first stage writes a
    candidate `daemon.json` to a temp path and runs `dockerd --validate --config-file <tmp>` inside
    a throwaway `docker:28-dind` container, once per candidate mirror URL, capturing exit code and
    stderr. `--validate` parses the configuration and exits without starting an engine, so this
    answers "is a path-bearing mirror URL even accepted?" without touching the host daemon.

    Pin the dind image by digest, not by tag, and record the digest in the evidence file (ADR-004
    house rule). `set -euo pipefail`; no `|| true` except a documented teardown; remove every
    container it creates on EXIT.

    Task 2's pull stage has nothing to measure and must be skipped — say so in the evidence file
    and go straight to Task 3 with the CONFIRMED verdict. Do not manufacture a workaround.

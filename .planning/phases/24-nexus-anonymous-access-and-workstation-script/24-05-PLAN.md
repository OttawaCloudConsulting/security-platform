<objective>
Close the Docker half of NEXUS-02 in the live gate: the full anonymous client handshake, the realm
that makes it possible, the URL shape that actually works, and the boundary anonymous read must
not cross.

Purpose: 24-RESEARCH.md contains a correction worth respecting — a first causal test fetched the
Docker manifest with no `Authorization` header, saw 200 with the `DockerToken` realm removed, and
concluded the realm was unnecessary. It is necessary; no Docker client ever makes that request. A
gate that repeats the header-less test would enshrine the wrong conclusion. This plan writes the
gate that performs the request sequence a real client performs.

Output: four live checks that make the Docker claim measurable, and a non-vacuity proof that
removing the realm turns the handshake check red.
</objective>

    **`ANONYMOUS-PULL-DOCKER`** (24-W0-05) — the full client handshake, no credentials anywhere,
    five ordered legs each with its own assertion and failure message:

    1. `GET /v2/` → expect **401** carrying a `WWW-Authenticate: Bearer` header. A 200 here is a
       failure, not a shortcut: it means the registry is not issuing challenges and the rest of the
       sequence would measure nothing.
    2. Parse `realm` and `service` out of that header. Parse them — do not hardcode the values the
       research happened to observe, or the check silently stops testing the server's actual
       challenge.
    3. `GET <realm>?service=<service>&scope=repository:docker-proxy/library/alpine:pull` → expect
       200 and a non-empty `.token`.
    4. `GET /v2/docker-proxy/library/alpine/manifests/3.21` **with `Authorization: Bearer <token>`**
       and the OCI/Docker manifest `Accept` headers → expect 200 and a body that parses as JSON
       carrying `manifests` or `layers`.
    5. Follow one layer or one manifest reference to a blob: `GET /v2/docker-proxy/library/alpine/blobs/<digest>`
       with the same bearer header → expect 200 and a byte count above a floor justified in a
       comment (a full export of this image streamed 8,083,968 bytes; the floor must be far above
       a 401 challenge page and well below the measured size).

    Write, immediately above the check, the comment that records why every leg is present: with
    `DockerToken` inactive the token endpoint STILL returns 200 and only the bearer-carrying
    manifest request returns 401 — and it does so for an ADMIN-issued token too, so this realm
    governs bearer validation generally rather than anonymity. State that a header-less manifest
    GET returns 200 even with the realm removed and must never be accepted as evidence; that exact
    test produced a wrong conclusion during this phase's research and was caught by review.

    **`ANONYMOUS-WRITE-DENIED`** (24-W0-08) — two assertions, one check. POST a **structurally
    valid** proxy repository body (same shape as the ones the chart's `-repos` ConfigMap ships)
    under a name that does not exist, e.g. `anon-write-probe`, with no credentials: expect exactly
    **403**. Then GET that repository name **with** the admin credential: expect **404**, proving
    nothing was created. The comment must record why the body must be valid: a malformed body
    returns 400, and a check that accepts "not 2xx" would pass for the wrong reason and would keep
    passing even if anonymous write were actually open (Pitfall 5). Treat any 2xx on the POST as a
    hard failure naming a privilege-escalation regression.
  </action>

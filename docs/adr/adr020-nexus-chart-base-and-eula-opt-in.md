# ADR-020: Nexus Chart Base, EULA Opt-In and the Unset Helm Proxy Remote

**Status:** Accepted
**Date:** 2026-09-18
**Addresses:** NEXUS-01 — a public Helm chart deploys Nexus Repository with npm, PyPI, Docker and Helm proxy repositories configured — and NEXUS-03 — the chart uses the cluster's default StorageClass unless the consumer overrides it

## Context

- **There is no Sonatype-published Helm chart named `nexus3`, so the phase's locked decision to "use the official upstream `nexus3` chart" was not satisfiable as written.** `helm search repo sonatype --versions` against `https://sonatype.github.io/helm3-charts/` returns exactly seven charts, and `nexus3` is not among them: `nexus3` is the name of Sonatype's *Docker image* (`docker.io/sonatype/nexus3`) and of a community *chart*, not of anything Sonatype publishes to Helm. Of the seven, only two are candidates for a single-instance homelab. `nexus-repository-manager` is **DEPRECATED**, frozen at chart 64.2.0 / app 3.64.0 since February 2024, and carries Sonatype's own archive notice on `github.com/sonatype/nxrm3-helm-repository` (repository `archived: true`, last push 2024-02-27) warning that "deploying Nexus Repository in containers with an embedded database has been known to corrupt the database under some circumstances" and that the HA chart is "our only supported Helm chart". `nxrm-ha` is supported, but defaults to `replicaCount: 3` with `clustered: true`, mandates an external PostgreSQL database, and gates on a Pro license file — three conditions that each contradict this milestone's zero-ongoing-cost premise, and whose bespoke `storageClass.enabled/name/provisioner` block is not the standard `persistence.storageClass` passthrough NEXUS-03 assumes. Choosing an official chart therefore meant either running a security tool 32 releases behind against its own vendor's do-not-use advice, or paying for a license and a database.
- **Since Nexus 3.77.0 the free edition is Community Edition, which ships with an unaccepted EULA that returns HTTP 403 on every component download while metadata continues to return 200 — a failure mode that looks like success from every angle an operator normally checks.** Measured end to end on a fresh `sonatype/nexus3:3.96.0-ubi` container: repository creation returns 201, anonymous-access configuration returns 200, `GET /repository/npm-proxy/lodash` returns 200 with 249,641 bytes of metadata, and `GET /repository/npm-proxy/lodash/-/lodash-4.17.21.tgz` returns **403** with a 192-byte body reading "You must accept the End User License Agreement (EULA) through the onboarding wizard or REST API before proceeding." `POST /service/rest/v1/system/eula` with the returned object's `disclaimer` echoed back verbatim and `accepted` set to true returns **204**, after which the identical tarball request returns 200 at **318,961** bytes. The POST is idempotent: a second call returns 204 again. The sequence was repeated on a third container booted with precisely the two properties the chart renders into `/nexus-data/etc/nexus.properties` (`nexus.datastore.enabled=true` and `nexus.loadAsOSS=true`) and every status code was identical — **`nexus.loadAsOSS=true` does not bypass the Community Edition EULA gate.** The chart is deployed, the pod is Ready, all four proxies are visible in the UI, `helm status` reads `deployed`, and nothing can be downloaded.
- **Turning on the upstream chart's own provisioning Job would re-enable the deprecated Groovy scripting API that this phase's design explicitly rejects.** The subchart gates `templates/configmap-properties.yaml` on `config.enabled`, and that path emits `nexus.scripts.allowCreation=true`. With the property absent — the state a default install is in — `POST /service/rest/v1/script` is refused with **410**, measured live on the same container. The upstream Job is also not a Helm hook, so it cannot be ordered against an ArgoCD sync, and it cannot accept the EULA in either configuration.
- **There is no general-purpose Helm chart repository left to point a Helm proxy at by default.** Helm Hub has been defunct since November 2020, and Artifact Hub is a cross-repository *search index*, not a repository serving a single `index.yaml` that Nexus can proxy. The one classic index still responding — `https://charts.helm.sh/stable`, measured at 200 and 9,839,197 bytes direct, 200 and 7,243,278 bytes through the proxy — has been archived and read-only since that same date. Any default this chart shipped would either be an archive or someone else's vendor.
- **This record extends two accepted decisions rather than reopening either.** ADR-010 established the correct framing for Nexus as a supply chain control; this chart is the first executable expression of that framing. ADR-007 established that Helm values belong in version-controlled files rather than in `--set` flags on a command line; the wrapper's `values.yaml` and the consumer-override surface described below are that convention applied to a chart this project now ships. Neither file was edited — the ADR directory is append-only per this repository's `CLAUDE.md`.

## Decision

- **Wrap the community `stevehipwell/nexus3` 5.26.0 chart as a subchart dependency, pinned by a committed `Chart.lock`; do not fork it and do not vendor it.** It is MIT-licensed, an ArtifactHub verified publisher, actively maintained (178 stars, 94 forks, pushed 2026-09-08), and it deploys Sonatype's own official `docker.io/sonatype/nexus3` image — the chart is community, the running software is not. It satisfies every other locked decision of the phase as written: a StatefulSet with one replica, an embedded datastore, no license file, an empty `tag:` that resolves to the subchart's `appVersion`, and a standard `persistence.storageClass` passthrough. Consuming it as a `dependencies:` entry rather than copying it into this project keeps upstream fixes reachable through a version bump instead of a merge.
- **Ship a purpose-built post-install/post-upgrade hook Job and keep `nexus3.config.enabled: false`, so the deprecated Groovy scripting API stays off.** The Job polls readiness under a bounded timeout, accepts the EULA when permitted to, and upserts the four proxy repositories over the REST API: `GET` first, then `POST` on 404 and `PUT` on 200. A blind repeat `POST` returns 400 on an existing repository, so the lookup is not defensive decoration — it is what makes a re-run of `helm upgrade` safe. Being a Helm hook rather than a plain Job is intended to give it a defined position in an ArgoCD sync — intended, not observed; see item 3 below.
- **Make EULA acceptance an explicit opt-in: `eula.accepted: false` is the shipped default.** A public chart must not accept a licence agreement on a consumer's behalf, silently, at install time, for whoever runs `helm install`. The Job performs the acceptance call only when the consumer sets the value to `true`, and the chart documents the agreement's URL so the decision is informed rather than incidental.
- **Ship no default for the Helm proxy's remote URL; document consumer-appropriate examples instead.** `repos.helm.remoteUrl` is explicitly `null` in `values.yaml`, and the chart README names realistic choices a consumer might actually mirror. Defaulting to an archive that stopped accepting charts in 2020 would have shipped a proxy that looks configured and serves nothing current.
- **Ship no admin password.** `nexus3.rootPassword.secret` names a Secret the consumer creates, is `null` by default, and is `required` at render time: a `helm template` with no values supplied fails with a message naming the value rather than rendering a default credential. This is asserted by the phase's own offline gate and is not relaxed for any reason, including scanner coverage.
- **Set `nexus3.persistence.enabled: true` and deliberately omit `nexus3.persistence.storageClass`, so Kubernetes substitutes the cluster's default StorageClass (NEXUS-03).** The key is absent rather than empty: the subchart guards on `{{- with .Values.persistence.storageClass }}`, so omitting it emits no `storageClassName` field at all, whereas an empty string emits `storageClassName: ""` and explicitly *disables* dynamic provisioning. A consumer overrides it with a single `--set nexus3.persistence.storageClass=<class>` or the equivalent values entry. The upstream default is `persistence.enabled: false`, which would have given a stateful service an `emptyDir`, so the enable is a correction, not a preference.

## Consequences

**Improved:** the whole path is measured, not argued. On a real `kind` cluster, `helm install` of the wrapper chart completed, the hook Job reached `condition met`, and all four proxy repositories were created on the first pass — `npm-proxy`, `pypi-proxy`, `docker-proxy` and `helm-proxy` each `action=created (HTTP 201)` — then updated on an immediate second pass, each `action=updated (HTTP 204)`, proving the GET-then-PUT branch executes rather than a repeat blind POST. The EULA call returned 204 on both passes. Against a container booted from the chart's own image reference (`docker.io/sonatype/nexus3:3.96.0-ubi`, resolved from the subchart's `appVersion`), a post-EULA `lodash-4.17.21.tgz` fetch through `npm-proxy` returned HTTP 200 at 318,961 bytes. The phase's offline gate reports `PASS - 16 checks, 0 failures` with no skipped check, and its live smoke reports `ALL PASS - 12 live check(s) executed and passed; 0 sub-check(s) skipped`. NEXUS-01 is therefore evidenced end to end — deployed, provisioned, and able to serve a real artifact — rather than inferred from a successful render.

**Improved:** NEXUS-03 is a property of the rendered manifest rather than of documentation. With no `storageClass` supplied, the rendered PersistentVolumeClaim carries no `storageClassName` field at all, which is the only form that lets the cluster's default class apply; with `nexus3.persistence.storageClass` set, the field appears with the consumer's value. Both renders were measured. The same discipline applies to the credential guard: a default `helm template` exits non-zero with a message naming `nexus3.rootPassword.secret`, so a missing Secret is a loud render failure rather than a Nexus instance reachable with a known password.

**Tradeoff — an unsigned community chart is now on this project's dependency path.** `stevehipwell/nexus3` reports `verified_publisher: true` and `signed: false` on ArtifactHub, and "verified publisher" attests control of the publishing domain, not review of the code. A chart bump therefore pulls in templates that no signature covers and that this project has not audited line by line. What is mitigated: the dependency is pinned in `Chart.lock` by digest, the deployed container image is Sonatype's official one rather than a community rebuild, and the substitution was made consciously and recorded here rather than performed silently inside a plan. What is not mitigated: if the upstream repository were compromised, a `helm dependency update` run without reading the diff would carry it into a cluster. The control is the lock file plus a human reading what a bump changes.

**Tradeoff — NEXUS-01's Helm proxy is only configured once the consumer supplies a remote.** Shipping no default means a plain `helm install` yields three working proxies and one that the chart leaves for the consumer to point somewhere. The requirement's word "configured" is satisfied by the repository definition and the documented one-value completion, not by a working mirror out of the box. The alternative — defaulting to `https://charts.helm.sh/stable` — would have satisfied the same sentence more literally while proxying an archive that has been read-only since 2020, which is worse for every consumer who did not read the values file.

**Tradeoff — Community Edition's ceiling is real and this chart cannot raise it.** Sonatype documents Community Edition as supporting up to **40,000** total components and **100,000** requests per day, beyond which "Community Edition's safeguards will pause the addition of new components until usage returns below both thresholds". That is comfortable for the single-developer practice this stack is designed for and inadequate for a team CI fleet, and no chart value changes it — the only remedies are a Pro license or a different product. It also interacts with the floating version decision below: the EULA gate and these limits both arrived in a specific Nexus release (3.77.0), so a future release can alter the terms of the free tier without any change to this repository.

**Tradeoff — the EULA opt-in means a default install downloads nothing.** With `eula.accepted: false`, the chart installs cleanly, the pod becomes Ready, the proxies exist, and every component fetch returns 403 — exactly the confusing state described in the Context above, now reached by the consumer's own deliberate default rather than by surprise. The mitigation is documentation: the chart README names the value, the agreement, and the 403 symptom together, so the one-line fix is discoverable from the symptom. Accepting on the consumer's behalf would have been friendlier and would have made this chart perform a legal act for a party that never saw the agreement.

**Tradeoff — subchart pin freshness.** `Chart.lock` pins `stevehipwell/nexus3` at **5.26.0**, and nothing in `security-platform`'s automation will ever bump it. `.github/dependabot.yml` in that repository declares a single `package-ecosystem: "github-actions"` entry, and **Dependabot** has no Helm chart-dependency manager at all — there is no configuration of it that would watch a `dependencies:` block in a `Chart.yaml`. **Renovate**'s `helmv3` manager does exactly that, but adopting a second bot is a repository-wide decision about tooling, noise and review load that this phase has no mandate to make, and no Renovate configuration exists in that repository today. The gap is therefore **deferred as a follow-up decision for the repository as a whole, not dropped**: it is recorded here precisely so that it is decided rather than forgotten. Until that decision is taken, the subchart — and with it the Nexus `appVersion` that the floating image tag resolves to, currently 3.96.0 — moves only when a human edits `Chart.yaml` and regenerates the lock. `Chart.lock` is the control point, and the practical consequence is that the floating-tag decision is far softer in practice than it reads: drift happens on a deliberate bump, not on a Tuesday. Nothing here should be read as closing the freshness question.

## What was NOT verified

What WAS measured in this phase and must not be re-litigated: the Community Edition EULA gate end to end on a fresh 3.96.0 container (403 at 192 bytes before, 204 from the acceptance POST, 200 at 318,961 bytes after, and the same sequence again under the chart's exact rendered `nexus.properties`); the full REST status-code matrix for all four proxy formats, identical across npm, pypi, docker and helm — `GET` 404, `POST` 201, `GET` 200, a repeat `POST` **400**, and `PUT` 204; the storageClass-by-omission render, with and without a consumer override; the Groovy scripting API's **410** refusal when `nexus.scripts.allowCreation` is absent; `yamllint -d relaxed` failing with a syntax error on Helm Go templates while passing on `Chart.yaml` and `values.yaml`, which is why the host repository's pre-commit hook carries `exclude: ^kubernetes/.*/templates/`; a second independent live smoke green on the chart as committed (`ALL PASS - 12 live check(s)`, 0 skipped, on a real `kind` cluster with the hook Job reaching `condition met`); and the CI-equivalent Checkov measurement, which reproduced the pipeline's pinned `ghcr.io/bridgecrewio/checkov:3.3.17` container and found it ships its own Helm v3.22.0, so its helm runner does engage — **14 failed checks before the chart, 14 after, an identical `check_id` plus `file_path` set, with zero `CKV_K8S_*` or `CKV2_K8S_*` findings in either, and exit 1 both before and after without `--soft-fail`, the setting CI actually uses.**

1. **Checkov's coverage of this chart is measured at zero, and that is a finding rather than a clean bill of health.** The assumption that the helm framework would engage in CI is closed by measurement — it engages, runs `helm dependency update` successfully, and then fails at `helm template` on the chart's own `required` credential guard, logged at `WARNI` and not raising the exit code. So the chart adds no findings to CI because **CI does not scan it**; those are the same fact stated twice and only the first half is good news. Rendered locally with a dummy Secret name and the EULA value supplied, the manifest produces 24 kubernetes-framework findings — 5 on this phase's own wrapper resources and 19 on the subchart's StatefulSet and its Services, ServiceAccount and ConfigMaps — none of which reach the pipeline today. What remains unverified is therefore the chart's Kubernetes security posture *as the pipeline sees it*, which is nothing. A later phase must choose deliberately between accepting the blind spot with the latent set documented, feeding the scanner a values file naming a dummy Secret (which reintroduces the question of a scanner-only file drifting from the real one), or committing a rendered manifest for scanning (which drifts by construction). **The `required` guard must not be weakened to obtain coverage** — trading a no-default-credential guarantee for a scanner's convenience is the wrong direction, and the guard is a locked mitigation of this phase's own threat model.
2. **The Docker proxy's `docker.pathEnabled: true` shape is accepted and stored, but no image was ever pulled through it.** The API accepts the body and the setting reads back correctly, which is why the repository exists and is online; an actual `docker pull` through the proxy needs ingress and TLS, which belong to a later phase. If the path-based connector turns out to be the wrong shape, correcting it means recreating the repository rather than editing it.
3. **ArgoCD's treatment of this chart's hook annotations is training knowledge, not an observation.** The claim that ArgoCD maps `helm.sh/hook: post-install,post-upgrade` to PostSync and honours `argocd.argoproj.io/sync-options: Replace=true` was not tested in this phase, and no ArgoCD instance was involved at any point. The annotations are cheap either way, and the phase that introduces ArgoCD is where they get exercised.
4. **Whether ArgoCD resolves the Helm subchart dependency itself was likewise not tested.** The chart deliberately does not commit `charts/*.tgz` — the tarball is gitignored — on the understanding that the deploying tool fetches it. If that turns out to be false, the tarball must be committed after all, which changes the repository's scanning surface as well as its contents. Verify before the first ArgoCD-managed install, not after.
5. **`provision.readiness.attempts` and `provision.readiness.intervalSeconds` remain present-but-unread, and no plan in this phase resolved them.** They appear in `values.yaml` and the chart README documents them honestly as inert; the provisioning script uses its own bounded poll and never reads them. Resolving them means either wiring them through the Job's environment contract and the live smoke that asserts it, or deleting them and updating the README's values table and limitations together. Both are chart edits in `security-platform`, which this documentation repository cannot make, so the item is carried forward rather than closed here.
